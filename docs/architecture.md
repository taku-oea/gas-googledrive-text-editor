### クライアントのファイル分け

クライアントは GAS が配る `<script type="module">` 一枚で動きます（`src/js.html`）。
もとは 1.7 万行の 1 ファイルだったものを、2 種類に分けて持っています。

| 置き場所 | 形 | 中身 |
|---|---|---|
| `client/lib/*.js` | 本物の ES モジュール（`import` / `export`） | 依存の無い純粋な部分。テストから直接 `import` できる |
| `client/app/*.js` | まだモジュールにしていない断片 | 残り全部。ファイル名の番号順にそのまま連結し、全ファイルが 1 つのスコープを共有する |

`tools/build-app.mjs` は、lib を依存の順に並べて `import` 行と `export` の語だけを外し、
その後ろに client/app を番号順につないで `src/js.html` を作ります。**コードは 1 文字も書き換えません**
（esbuild でまとめるとトップレベルの `const` / `class` が `var` に変わるため、あえて使っていません）。
分割・移動のたびに、生成物のトップレベルの文が分割前の `js.html` と 1 文字も違わない（並び順だけが違う）
ことを確かめています。

- client/app からは、lib の関数を今までと同じ名前で呼べます（`import` を書く必要はありません）
- 全体が 1 つのスコープになるので、**トップレベルの名前が重なるとビルドが止まります**
  （`client/app/590-wiring.js:359:10: Identifier 'detectEol' has already been declared` のように元の位置で出ます）
- lib で使える書き方は `import { a } from './x.js'`（lib 同士）と、宣言にじかに付ける `export` だけです。
  default export・`export { a as b }`・`import * as`・外部パッケージの import はビルドが止めます
  （vendor や mermaid は今までどおり client/app から `import()` で読みます）
- client/app は**番号順が評価順です。** トップレベルで実行される文（イベント配線・起動）は、使う宣言より
  後ろのファイルに置きます（`580-boot.js` → `590-wiring.js` が最後）。番号は 10 刻みなので、
  あいだに足すときは `265-xxx.js` のように挟みます
- client/app に残っているのは、共有の状態（`App`・`el`・`Tree` など）や画面に触るものです。
  lib へ移すときは、その依存を引数で受け取る形にしてから移します

| lib | 中身 |
|---|---|
| `errors.js` | `ApiError`・サーバー応答の解釈（`unwrapResponse`） |
| `format.js` | バイト数・相対時刻・時刻・拡張子の書式 |
| `eol.js` | 改行コードの判定と往復・インデントの推定 |
| `dom.js` | 要素の組み立て（`h`）・アイコン・IME の判定 |
| `platform.js` | Mac かどうか・修飾キーの表記（`IS_MAC` / `MOD`） |
| `font.js` | エディタのフォント（候補の一覧・名前の丸め・`font-family` の組み立て・インストール済みかの判定）。サーバー側の `DriveService.cleanFontFamily_` と同じ規則 |
| `text-codec.js` | 文字コード（UTF-8 / Shift_JIS の判定と符号化） |
| `search.js` | 全体検索の照合（一致する行の抜き出し） |
| `term-parse.js` | ターミナルのコマンド行（字句・パイプ・オプション・glob・grep のパターン・並列実行・別名） |
| `md-edit.js` | Markdown の入力バーの編集（行の選択・見出し・行頭記号・ひな形） |
| `cm-theme.js` | CodeMirror の配色（`cmTheme` / `cmHighlightStyle` と色の表）・日本語の文言（`PHRASES`） |
| `preview-policy.js` | プレビューの sandbox・DOMPurify の設定・外部 URL の判定・drawio の判定 |
| `store-cache.js` | 本文の LRU キャッシュの芯（`Store` の相乗り・追い出し）。通信する `readFile` / `prefetchTabs` は client/app（110）が足し、開いているタブを守る判定は `Store.isOpen` に差し込む |
| `file-index.js` | クイックオープン用のファイル名の索引の芯（`FileIndex` の保存・読み込み・パス）。索引を作る `build` などは client/app（430）が足す |

| `tree-model.js` | サイドバーのツリーのデータモデル（`Tree`・`sortChildren`・`folderSig`）。消したノードの後始末（ファイル名の索引・閉じたタブ）は client/app が `Tree.onRemoved` に差し込む |

オブジェクトの一部（依存の無いプロパティ＝芯）だけを移すときは `node tools/split-core.mjs <app ファイル> <名前> <lib.js> "<説明>" <プロパティ>…`
を使います。lib 側に `export const <名前> = { … }` ができ、client/app 側は元の場所で `Object.assign(<名前>, { … })` して残りを足します。
芯が client/app のものを 1 か所だけ使っているときは、その呼び出しを差し込み口（`Tree.onRemoved`・`Store.isOpen` など）に
置き換えてから移します。

移すときは `node tools/move-to-lib.mjs <lib.js> "<説明>" <名前>…` を使います。直前のコメントごと移して
`export` と lib 同士の `import` を付け、client/app の宣言に依存しているものは止めます。

かつ HTML のパース中に依存グラフの取得を始めたいためです（後述の高速化を参照）。

## サーバー関数一覧

すべて例外を投げず、必ず次の形を返します。エラーは日本語の文字列として
クライアントへ届き、画面に表示されます。

```javascript
{ ok: true,  data: <任意> }
{ ok: false, error: "日本語メッセージ", code: "...", detail: <任意> }
```

`code` は `FORBIDDEN` / `NOT_FOUND` / `CONFLICT` / `TOO_LARGE` / `NOT_TEXT` /
`LOCKED` / `UNKNOWN` のいずれかで、クライアントの分岐に使います。

想定外の例外（`appCode` を持たないもの）は、中身を画面に出さず「参照: xxxxxxxx」の
参照番号だけを返します（内部の関数名や URL が混じりうるため）。中身とスタックは同じ番号で
Cloud Logging に `[UNHANDLED xxxxxxxx]` として残るので、利用者から番号を聞けば引けます。
利用上限・時間切れだけは利用者が対処できるので、それと分かる文にしています。

### 高速化のために入れてあること

推測で最適化しないよう、`guard_` が全 API の所要時間を
`[perf] <API名> <ms>` の形で実行ログに出します（Apps Script エディタの
［実行数］か Cloud Logging）。クライアント側も起動時間を `console.log` します。

**Drive への問い合わせを並列に（`src/DriveRest.gs`）**
`DriveApp` のゲッターも拡張サービス（`Drive.*`）も 1 呼び出し = 1 HTTP 往復で、必ず直列に
走ります。`getBootstrap` は以前、ルート 8 個の `getFolderById().getName()` → 一覧 → 本文を
直列に回していました（往復 10 回以上）。いまは `UrlFetchApp.fetchAll` で
「ルートごとの `files.get`」「ルート + 展開中フォルダの `files.list`（15 親ずつ）」
「アクティブなタブの `files.get` と `alt=media`」を **1 回で同時に**投げ、
`PropertiesService` は `getProperties()` 1 回、`CacheService` は `getAll` / `putAll` 1 回ずつです。
`readFile` はメタデータと本文を並列に、`saveFile` は `uploadType=multipart` の PATCH 1 本で書き、
応答に入っている新しい `modifiedTime` をそのまま返します（以前は `setContent` 後に
最大 3 回の再取得と 750ms の `sleep` で追いかけていました）。全体検索の本文 30 件、
一時メモの掃除、同名チェック（`getFilesByName` のイテレータ）も同様に 1 本の `files.list` か
並列 PATCH に置き換えています。REST が使えない実行では自動的に旧経路（`*Legacy_`）へ落ちます。

**段階タイマー**
`guard_` は `fn(T)` の中で `T.mark('props')` のように打った区切りを
`[perf] getBootstrap 1100ms stages email=20 props=50 cache=40 fetch=620 assemble=15 total=745`
の形で出します。`doGet` も `template=` / `evaluate=` を出すので、テンプレート評価の重さが分かります。

**起動（前回の状態を HTML に埋めて、サーバーを待たずに描く）**
実測では CodeMirror は HTTP キャッシュから 80ms ほどで揃うのに、`getBootstrap` の往復が
2.5 秒前後（サーバー内 1.3 秒 + GAS の起動と転送で 1.4 秒）あり、起動時間のほぼ全部を
占めていました。そこで `doGet` が **UserProperties と CacheService だけを読んで**
（Drive は見ない・100〜200ms）前回の状態を `window.__BOOT` として HTML の末尾に埋め、
クライアントはモジュール評価直後にそれを同期で描きます。CodeMirror が届いた時点で
アクティブなタブの本文で `EditorView` を 1 回だけ作り、`getBootstrap` の応答が届いたら
フォルダごとの署名（id・名前・更新日時・サイズ）を比べて変わった所だけ描き直します。
アクティブなタブの本文が Drive 側で新しくなっていれば、未編集なら選択とスクロールを
保ったまま差し替え、編集中なら触らず保存時の競合検出に任せます（`reconcile`）。
`<header>` と `<main>` は最初から表示し、ツリーにはスケルトン行を置いています。
初回（ルート未設定）や 6 時間以上空けたときはスナップショットが無いので、従来どおり
`getBootstrap` を待って描きます。

**CodeMirror の配信（バンドル 1 本を自前の配信先から）**
esm.sh の `?external=` 付き URL は「深い URL へ再エクスポートするだけのスタブ」を返し、
さらに `crelt@^1.0.6` のような版未固定の依存を `max-age=600` のスタブ経由で引くため、
起動に 32 ファイル / 4 段の直列取得が要り、10 分以上空けると一部が再検証されて 100〜400ms 遅れていました
（実測: 1 回目 `cm-ready` 484ms、2 回目 107ms）。esbuild で 1 本にまとめて配信先に置き、起動に要る
チャンク 2 つを `modulepreload` で同時に取らせます。全部 immutable なので 2 回目以降は 0 リクエストです。

**起動（サーバー往復と CDN 取得の並列化）**
`getBootstrap` と CodeMirror の CDN 取得は互いに独立なので、どちらも待たずに同時に走らせます。直列にすると、どちらもコールドスタート時に数秒かかるため
起動時間がまるごと足し算になります。

**起動（往復を 1 回に）**
セッション復元は以前 `getBootstrap` → `listEntriesMulti` → `readFile` の
直列 3 往復でした。`getBootstrap` がサーバー側でセッションを読んでいるので、
展開フォルダの中身（`expandedEntries`）とアクティブタブの本文（`activeFile`）を
同じ応答に積んで 1 往復にしています。本文が 200KB を超える場合は同梱せず、
クライアントが従来どおり `readFile` で取りに行きます。

**CDN のウォーターフォール**
esm.sh は `?external=` を付けると「深い URL へ再エクスポートするだけのスタブ」を
返すため、依存グラフは 4 段の直列取得になります（実測 32 ファイル / 428KB。
うち 1 段目 1.3KB と 3 段目 7.7KB は中身をほぼ運ばない純粋な往復レイテンシ）。
import map を `src/importmap.html` として `<head>` に置き、起動時に必ず使う
6 パッケージに `modulepreload` を張って HTML のパース中に取得を始めます。

**一覧取得（Drive API v3）**
`DriveApp` のイテレータはファイル 1 件ごとにゲッターを呼ぶ必要がありますが、
`Drive.Files.list` なら `fields` を絞った 1 リクエストで全件のメタデータが返ります。
複数フォルダも `('a' in parents or 'b' in parents)` で 1 リクエストに畳めます。
フォルダのアクセス可否の検証は今までどおり `DriveApp.getFolderById` の
try/catch で行い、一覧の取得だけを API に移しています。

拡張サービスが無効な場合とクエリが例外を返した場合の 2 段で
`DriveApp` の経路にフォールバックします（共有ドライブでの挙動が未検証のため）。

**キャッシュ**
本文は gzip + Base64 で載せます。テキストは 4〜5 倍圧縮が効くので、
生のままだと 80KB で諦めていたファイルも 1 値 100KB の枠に収まります
（実質 200〜300KB 程度まで）。

**使われていない処理の削除**
`listEntries_` は毎回パンくずを生成していましたが、サイドバーがツリーになってから
誰も使っていませんでした（生成には親を最大 12 段遡る `DriveApp` 呼び出しが必要）。
必要なのは `resolveFolderRef`（選択画面の表示）だけなので、そちらでのみ作ります。

**Markdown プレビューのブロック単位差分描画**
以前は打鍵のたびに全文を `marked.parser` と DOMPurify に通して `innerHTML` を全置換していたので、
画像・iframe・mermaid の図が毎回点滅していました。いまは marked の lexer でトップレベルのブロックに分け、
「種類 + 元テキスト + 参照リンク定義」をキーにして sanitize 済み HTML をキャッシュし（LRU 500 件）、
DOM もキーで突き合わせて変わったブロックだけ作り直します（`.mdb` で包み、`data-src-line` はそこに付ける）。
mermaid の描き直しも新しく入ったブロックの中だけです。小さい文書（3 万文字未満）は 120ms、
それ以上は 250ms のデバウンスで描きます。

**クライアントの描画**
- `onDocChanged` は、表示に出る状態が実際に遷移したときだけ再描画します。
  以前は 1 打鍵ごとに全タブの DOM を作り直し、全ツリー行を
  `querySelectorAll` していました
- ツリー行のツールチップはホバー時に組み立てます。以前は行ごとに
  祖先を遡るパス生成と `toLocaleString`（Intl は遅い）を実行していました
- 絞り込み入力は 120ms デバウンスします

**本文のクライアント側キャッシュと先読み（`Store`）**
一度読んだ本文はタブを閉じても LRU（20 件・8M 文字）に残し、開き直し・タブ切替は 0ms で出します。
出したあとは裏で `readFile(id, knownUpdatedAtIso)` を呼び、更新日時が同じなら本文は届かず
（`unchanged:true`）、変わっていて未編集なら選択とスクロールを保ったまま差し替えます。
起動直後の空き時間には、開いているのに本文をまだ読んでいないタブを `readFilesMulti` の
1 往復でまとめて読みます。ツリーではポインタが 150ms 止まったファイルの本文と、300ms 止まった
未読込フォルダの一覧を先に取っておきます（省データ設定・2G 判定では動かしません）。
展開済みフォルダを開き直したとき、前回の取得から 60 秒より古ければ裏で取り直し、
中身が変わっていたときだけ描き直します。保存に成功した本文もそのままキャッシュに入ります。

**クライアントの計測**
起動は `performance.mark`（`html-head` → `module-eval-start` → `boot-start` → `bootstrap-resolved` /
`cm-ready` → `tree-painted` → `editor-interactive`）を打ち、起動完了時に `console.table` で出します。
あわせて HTML の `encodedBodySize` / `decodedBodySize`（圧縮配信か）、esm.sh の取得数とキャッシュ命中、
`location.origin` と前回のオリジン（localStorage が再読み込みをまたいで残るか）も出します。
操作（`rpc.<関数名>`・タブ切替・保存・ツリー描画・プレビュー）は `Perf.start()` で溜め、
コマンドパレットの **「パフォーマンス計測を表示」** で p50 / p95 を見られます。
`index.html` の `<head>` では `google.script.run` が使えれば `getBootstrap` を先に発火し、
モジュール（約 260KB）の受信と compile を待たずに往復を始めます（使えなければ従来どおり js 側で呼びます）。

**ブラウザから Drive API を直接**
`listEntries` / `listEntriesMulti` / `readFile` / `readFilesMulti` / `saveFile` / `searchContents` /
`listRevisions` / `readRevision` は、トークンが届いていれば `google.script.run` を通さず
`www.googleapis.com` を直接呼びます（`client/app/070-direct.js` の `Direct`）。往復は 1〜2 秒 → 0.2〜0.5 秒になり、
GAS のコールドスタートに当たるのは起動時の `getBootstrap` だけになります。戻り値の形は
サーバー関数と同じで、エラーコードも同じものに写しているので、呼び出し側の分岐は変わりません。
競合検出も同じ手順（`files.get` で更新日時を確かめてから multipart の PATCH）です。
作成・改名・移動・複製・ゴミ箱も同じく直接呼びます（同名チェックは `files.list` 1 本、
移動は `addParents` / `removeParents` の PATCH 1 本）。アップロードと一時メモは引き続きサーバー経由です。
サーバー側の関数は全部残してあるので、`DIRECT_DRIVE_ENABLED=false` でいつでも戻せます（[security.md](security.md)）。
サーバー側の `renameFile` も同じくメタデータの PATCH 1 本で改名し、応答の `modifiedTime` を返します
（`setName` 直後の `getLastUpdated` は古い値を返すことがあり、次の保存が偽の競合になるため。
`DriveApp` は REST が使えないときのフォールバック）。「… のコピー」の空き名は、フォルダの中身を
一覧せず候補の名前ごとに `name = '…'` で問い合わせます（1 ページ 1,000 件を超えるフォルダで見落とさないため）。

**楽観的更新（改名・移動・ゴミ箱）**
結果が分かりきっている操作は画面を先に変え、Drive への往復（1〜3 秒）を待たせません。
改名はツリーとタブの名前を即座に書き換え、移動は行を移動先へ動かし、ゴミ箱は行を消します。
往復が返ってきたら成功・失敗のどちらもトーストで知らせ、失敗したときは元の状態に戻します
（ゴミ箱で閉じたタブは開き直します）。改名が Drive 側で確定するまでは、そのファイルの保存を
少し待たせます（改名で更新日時が進み、次回の保存が競合になるのを防ぐため）。
作成と複製は Drive が付ける ID が要るので待ちますが、以前のように親フォルダの一覧を取り直さず、
返ってきた 1 件をツリーへ差し込みます（往復 2 回 → 1 回）。

**一時メモの作成も待たない**
`Mod+Alt+N` は、Drive にファイルを作る往復（1〜3 秒）を待たずに空のタブを開きます。
ID が決まるまでは仮 ID（`new:…`）で動かし、返ってきた時点で実 ID に差し替えます
（`EditorState` には作った時点の ID が焼き込まれているので、`getTab` は仮 ID でも引けるようにしてあります）。
待っている間に書かれた内容は、ID が決まった直後にそのまま保存します。
待っている間にタブを閉じた場合、空なら作った実体をゴミ箱へ入れ、書かれていれば Drive に残して知らせます。
作成に失敗したときはタブを残し（内容を失わせない）、ステータスバーに理由を出して `Mod+S` で作り直せます。

**変更ログで「何が変わったか」をまとめて知る（`ChangeFeed`）**
以前は、展開し直したフォルダを 60 秒ごとに取り直し、キャッシュから出したタブも切り替えるたびに
更新日時を確かめていました（フォルダ・ファイルの数だけ往復が要る）。いまは起動後に Drive の
`changes/startPageToken` を 1 回取り、見えている間は 60 秒ごと・画面に戻ってきたとき・
フォルダを開き直したときに `changes.list` を 1 本だけ投げて、ルートをまたいだ変更を一度に受け取ります。

- 変わったファイルが読み込み済みフォルダの子なら、名前・置き場所・有無が変わったときだけ
  そのフォルダを取り直します。更新日時とサイズだけの変化なら行を書き換えるだけです
- 開いていて未編集のタブの中身が変わっていれば、選択とスクロールを保ったまま差し替えます
  （自分の保存は更新日時が一致するので無視します。編集中は触らず、保存時の競合検出に任せます）
- ファイル名の索引（`FileIndex`）も同じ変更で書き換え、フォルダが変わったら全体検索の
  フォルダ列挙を捨てます
- ログが生きている間（直近 2 分以内に問い合わせに成功している間）は、ログを取り始めた後に
  読んだ本文・一覧の再確認を省きます。タブの切り替えとフォルダの開き直しは往復ゼロになります
- 10 ページ（1 万件）で読み切れないほど溜まっていたら、ログを捨てて取り直し、開いている
  フォルダを取り直します。GAS 経由で動いているとき・ログを取れなかったときは従来の再確認に戻ります

**押した瞬間に読む**
ツリーの行を `pointerdown` した時点で本文の取得を始めます。`click` の確定より 100〜200ms 早く、
hover の 150ms 静止が間に合わなかったファイルでもその分だけ表示が早くなります。

### サーバー呼び出し回数の方針

`google.script.run` の往復は片道 0.3〜1 秒、コールドスタート時は数秒かかります。
そのため**編集セッション中にクライアントが呼ぶのは `listEntries` / `readFile` / `saveFile`
の 3 つだけ**です。キー入力・カーソル移動・言語切り替えでサーバーは呼びません。
`getBootstrap` / `listFolderChildren` / `resolveFolderRef` / `setActiveFolder` は
起動時とフォルダ切り替え時にだけ動く別枠、`createFile` / `renameFile` / `trashFile` は
ユーザーがボタンを押したときだけ動く別枠です。

タブの切り替え・ファイル名の絞り込み・言語モードの適用はすべてクライアント側で完結し、
サーバーを呼びません。

## 動作の仕組み（要点）

### キャッシュ

`CacheService.getUserCache()` を高速化のためだけに使います。**真実の保存先は常に Drive** で、
キャッシュが消えても動作は変わらず、遅くなるだけです。

- 一覧は `list:<folderId>` に **6 時間**残しますが、そのまま返してよいのは値の中の `fetchedAt`
  から **30 秒以内**のものだけです。それより古いものは起動時のインライン表示（後で本物と突き合わせる）
  にだけ使います。サイドバーの ⟳ ボタンで 30 秒を待たずに取り直せます
- アクティブなタブの本文は `snap:file:<fileId>` に 6 時間残します（`getBootstrap` と `saveFile` が書く）。
  これも起動時のインライン表示用で、`readFile` はキャッシュを見ずに毎回 Drive から取ります
  （メタデータと本文を並列に取るので、キャッシュを挟んでも速くならないため）
- 旧経路（REST 不可時）だけは従来の `f:<fileId>:<更新日時>` 本文キャッシュを使います
- 値は gzip + Base64 で載せ、1 値 100KB の制限に収まらないものはキャッシュしません

### 競合検出

1. `readFile` が返した更新日時をクライアントが保持
2. `saveFile` に毎回その値を渡す
3. サーバーで Drive の現在値と比較し、食い違えば保存せず `code:'CONFLICT'` を返す。
   基準値が空で来たとき（クライアントの不具合など）も、黙って上書きせず `CONFLICT` にする
   （上書きは画面で選んだときの `force` だけ）
4. クライアントが「差分を見る／上書き保存／Drive 側を読み込む／あとで決める」を選ばせる
5. 保存成功時は新しい更新日時を返し、クライアントが基準値を差し替える
6. 「差分を見る」で開いた比較ビュー（Drive 上の内容 ⇄ 編集中の内容）で決めた内容をタブへ反映したときは、
   タブの基準値を**比べた Drive の版の更新日時**へ進めて競合を解く（`advanceBaseFromDiff`）。
   進めるのはその版の日時だけなので、比較を開いたあとに別の人が保存していれば次の保存はまた競合になる

Drive v3 には更新日時を条件にした書き込み（`If-Match`）が無いので、比較は直前の GET で行っています。
GET と PATCH のあいだ（数百 ms）に他の人が保存した場合は検出できません。
同じ人の二重保存は `UserLock` で直列にしています。

### 自動保存

入力停止から 2 秒後に保存します（`Cmd/Ctrl+S` でデバウンスを飛ばして即時保存）。
ヘッダー右に `未保存 / 保存中… / 保存済み hh:mm:ss / 保存失敗 / 競合` を表示します。
保存のデバウンスと状態はタブごとに独立しています。同一ファイルへの並行保存はせず、
保存中に編集された場合は完了後にもう一度走ります。
ウィンドウのフォーカスが外れたときは、未保存のタブをすべて保存します。

### 一時メモ

とっさのメモ用に、保存先を決めないままタブを 1 枚開ける機能です。
VS Code の「無題のファイル」にあたりますが、**最初から Drive の実ファイル**である点が違います。

作られる場所は、既定ではマイドライブの

```
Googleドライブテキストエディタ / tmp /
```

です。フォルダ ID は `UserProperties` の `tmpFolderId` に覚えます。名前で毎回探すと
フォルダの列挙が毎回走るうえ、ユーザーが改名・移動した瞬間に二重に作ってしまうためです。
ID なら改名・移動されても同じフォルダを指し続けます。ゴミ箱に入れられていた場合だけ作り直します。

#### 置き場所は変えられる

**初回に必ず出る「編集するフォルダ」の画面**と、**設定の「一時メモの置き場所」**の
2 か所から変えられます。どちらも同じ `setTempFolder` を呼びます。

**選ぶのは「親フォルダ」で、実体は必ずその下の `<アプリ名> / tmp` です。**
選んだフォルダをそのまま一時メモ置き場にはしません。保存期間を過ぎたメモを
自動でゴミ箱へ移す掃除があるので、ユーザーが選んだフォルダをそのまま使うと、
**そこに元からあったファイルまで巻き込みます**。アプリが作ったフォルダの中に
閉じておけば、掃除が消してよいものしか入りません。共有ドライブの中も選べます。

| 覚えるもの | `UserProperties` のキー | 中身 |
|---|---|---|
| 親フォルダ | `tmpParent` | `{id, name}`。未設定なら既定（マイドライブ直下） |
| 実体 | `tmpFolderId` | いまの `tmp` フォルダの ID |
| 移し残し | `tmpMoveFrom` | 引っ越しで移しきれなかった古い `tmp` の ID の配列（新しい順・最大 5 件。以前の ID 1 つの形式も読む） |

親フォルダの**名前も**覚えているのは、置き場所を
「作業 / Googleドライブテキストエディタ / tmp」と画面に出すのに Drive を触らずに済ませるためです
（起動時の往復を増やさないため）。

**変えると、いまある一時メモもそこへ移します**（`moveTempFiles_`）。移動は
`addParents` / `removeParents` の並列 PATCH で、1 回の上限は 300 件です。
**Drive のファイル ID は変わらない**ので、開いているタブはそのまま使えます。
上限を超えた／権限で失敗したぶんは古いフォルダに残り、その ID を `tmpMoveFrom` に
覚えておきます。**同じ場所をもう一度選べば続きから移します。** 移しきる前に置き場所を
さらに変えた場合も、いまの `tmp` と覚えている移し残しを全部まとめて新しい場所へ移します
（以前は最後の 1 つで上書きしていたため、その前の移し残しを見失っていました）。

引っ越したあとの古いフォルダは残します。移しきれていないかもしれず、空に見えても
消してよいとは限らないためです（消すかどうかは人の判断に任せます）。

まだ一度も一時メモを使っていない場合は、**記録するだけで Drive にフォルダを作りません**。
初回の選択画面でここを変えても、フォルダができるのは最初の一時メモを作るときです
（「実際に使うまで作らない」方針をそのまま保っています）。

覚えていた親フォルダが消された／権限が外れた場合だけ、既定の場所へ戻して作り直します
（`NOT_FOUND` / `FORBIDDEN` のときだけ。通信の一時的な失敗でここを通ると、
選んだ置き場所が黙って既定に戻ってしまうため）。

**実体を Drive のファイルにしてあるのが要点です。** このアプリのタブ ID は
Drive のファイル ID そのものなので、一時メモは「置き場所が `tmp` なだけの普通のタブ」になり、

- 自動保存・競合検出・下書き・タブの復元が、通常のファイルとまったく同じ経路を通る
- セッションはサーバー（`UserProperties`）にあるので、**別の端末で開くと書きかけのメモが
  タブごと復元される**

の 2 つがそのまま手に入ります。「未保存バッファ」という別の状態を持たずに済みます。

**入口は 4 つ**：タブバーの空いているところをダブルクリック／タブバー右端の ＋／
サイドバーの 📝 ボタン／`Mod+Alt+N`。`Mod+N` を使っていないのは、
`Cmd+N`・`Ctrl+N`・`Cmd+Shift+N` がブラウザ側で予約されていて Web ページから奪えないためです。

**ファイル名**は `メモ 2026-09-11 1430.txt` のように日時を入れます。同じ `tmp` を
複数の端末が共有するので、`無題-1` 方式だと端末をまたいだときに衝突しやすいためです。
拡張子は設定で `.txt` / `.md` から選べます（言語モードは拡張子から決まるので無拡張にはしません）。

#### `Mod+S` の意味が変わる

一時メモでは `Mod+S` が「保存」ではなく **「保存先を決めて確定する」** になります
（VS Code の無題ファイルと同じ）。フォルダ選択画面を保存ダイアログとして開き、
フォルダとファイル名の両方を聞きます。

- **ファイル名の初期値は本文の 1 行目から作ります**（記号を落として 40 字まで）。
  とっさのメモは 1 行目が用件になっていることが多く、あとから探しやすくなります。
- **フォルダの初期値は前回の保存先**（`UserProperties` の `lastSaveFolder`）です。
  同じ場所へ続けて保存することが多いので、たいていは Enter 一発で終わります。
- 確定は `promoteTempFile` が **保存 → 改名 → 移動を 1 往復** で行います。分けて呼ぶと、
  途中で失敗したときに「移動はできたが名前は古いまま」という半端な状態が残ります。
  名前の衝突は、何かを書き換える前に移動先で確かめます。
- **キャンセルしても失うものはありません。** VS Code と違って内容は既に Drive にあるので、
  一時メモのまま残るだけです。
- 保存先がサイドバーに無いフォルダだった場合、保存した瞬間に一覧から消えたように見えるため、
  「このフォルダをツリーに追加しますか」と聞きます。

ツリーの「一時メモ」から普通のフォルダへドラッグしても同じことが起きます。
逆に普通のファイルを「一時メモ」へ放り込めば一時メモとして扱われます。
**一時メモかどうかは置き場所（`tmp` の中か外か）だけで決まります。**

#### 溜めっぱなしにしない

実ファイルなので、放っておくとマイドライブに溜まり続け、しかも全端末へ同期されます。
3 段構えで片付けます。

| きっかけ | 対象 | 動き |
|---|---|---|
| 中身が空のまま閉じた | そのメモ | 即ゴミ箱へ（保存確認もしない） |
| 12 時間に 1 回（メモ作成時／一覧を開いたとき） | 保存期間を過ぎたメモ | ゴミ箱へ |
| 同上 | 空のまま 24 時間経ったメモ | ゴミ箱へ（閉じる前にブラウザが落ちた残骸） |

保存期間は設定から変更でき、既定は 30 日、`0` で無期限です。設定の「いま片付ける」で
待たずに走らせることもできます。**完全削除はせず必ずゴミ箱までです。**

`tmp` フォルダは名前で探して使い回すので、置き場所を共有フォルダや共有ドライブにすると
複数の人が同じ `tmp` を使うことになります。そこで**掃除するのは自分のメモだけ**にしています
（マイドライブは所有者が自分、共有ドライブは最後に書いたのが自分のもの。判定できないものは残す。
`DriveService.isMyTempFile_`）。

掃除を起動時に走らせていないのは、起動の往復を増やさないためです。同じ理由で
`tmp` フォルダの実体は「実際に一時メモを使うまで作りません」。`getBootstrap` が返すのは
`UserProperties` に覚えている ID だけで（未使用なら `null`）、Drive は一切触りません。
そのため **サイドバーの「一時メモ」は、一度でも使うまで現れません**。

#### 画面上の扱い

「一時メモ」はサイドバー最上段の**固定セクション**です。通常のルート（`Tree.rootIds`）とは
別に `Tree.tmpRootId` で持っています。外す／並べ替える／数を数えるといった処理すべてに
例外条件を足さずに済むためです。ユーザーは外せません（最大 8 個のルート数にも数えません）。

タブには `tmp` バッジが付き、ヘッダーの状態表示は
`一時メモ · ⌘+S で保存先を決める` になります。自動保存の待ち時間は
通常設定と 5 秒のうち長いほうを使います。保存先も決まっていない書き殴りに、
通常ファイルと同じ 2 秒間隔で Drive を叩き続ける必要がないためです
（取りこぼしは localStorage の下書きとウィンドウ blur 時の一括保存が拾います）。

### ピン留め

よく使うファイルをサイドバー最上段の「ピン留め」セクションに置いておける機能です。
**ファイルの置き場所は変えず、参照だけを持ち上げます。**

狙いは「深い階層へ行き直す手間を無くす」ことです。ツリーは 1 階層ずつの遅延ロードで、
名前の絞り込み（`Mod+Shift+E`）は**読み込み済みの階層**しか対象にしません。
3 段開かないと辿り着けないファイルは、開くたびにそこまで降りることになります
（クイックオープン `Mod+P` は索引で配下すべてを探せますが、名前を覚えている必要があります）。

**入口は 5 つ**：「ピン留め」の見出しにホバーすると出る 📌 ボタン（いま開いている
ファイルを留める）／タブの右クリック →「ピン留めする」／ツリーの行の右クリック →
「ピン留めする」／ツリーからファイルを「ピン留め」の見出しへドラッグ＆ドロップ／
コマンドパレットの「ピン留めする」。複数選択した状態の右クリックからまとめても留められます。

記録するのは**ファイル ID・表示名・種別の 3 つと並び順だけ**です（本文も更新日時も
持ちません。真実の保存先は常に Drive）。保存先は `UserProperties` の `pins` で、
セッション（`session`）とは別の値にしています。セッションは「前回の画面」なので
タブを閉じれば入れ替わりますが、ピン留めは寿命が違うためです
（9KB 制限の枠も、溢れたときに落とす順番も分かれます）。上限は 40 件で、
超えたときは黙って古いものを落とさずに断ります（消えたことに気づけないため）。

`getBootstrap` は `UserProperties` を 1 回でまとめて読むので、**ピン留めのために
往復は増えません**。`doGet` が HTML に埋める起動スナップショットにも載るので、
サーバー応答を待たずに最初の描画で並びます。

#### タブの「ピン留め」との関係

同じものです。タブ側の旗（`tab.pinned`）はこの一覧を正として写しており
（`Pins.sync`）、入口がタブでもツリーでも行き先は同じ一覧になります。
同じ名前で別物が 2 つあると、どちらを操作したのか分からなくなるためです。
ピン留めしたファイルのタブは「他のタブを閉じる」「右側のタブを閉じる」の対象外に
なりますが、**× で手で閉じることはできます**（サイドバーに残るので、閉じても見失いません）。
比較タブは Drive 上のファイルに対応しないため、そのタブの中だけの旗として扱います。

#### 画面上の扱い

「一時メモ」と同じ**固定セクション**で、**0 件でも枠は出します**
（「一時メモ」と同じ位置に常にあるべきもので、無いと入口に気づけないため）。
空のときは件数の代わりに「タブやファイルを右クリック →『ピン留めする』」と書き、
見出しのボタンから 1 クリックで始められるようにしています。
ただし `Tree` のノードにはしていません。`Tree` は「1 ノード = 1 つの親」を前提に
していて、同じファイルが元のフォルダとピン留めの両方に出ると親が上書きされ、
移動・削除・絞り込みが壊れるためです。状態は `Pins` が持ち、描画だけを
`renderTree` に相乗りさせています。行には元のツリー行と同じ `data-node-id` を付けるので、
「開いている」「編集中」の色付けと hover の先読みはそのまま効きます。

- 名前の絞り込み中は出しません（読み込み済みでない階層のファイルも並んでいるため、
  絞り込み結果に混ぜると「一致したものが全部出ている」という読み方が崩れます）
- ツリーのキーボード操作（`↑↓`）の対象にも入りません（ツリーの行だけを辿ります）
- 表示名は最後に見た時点のもので、開いたときに実名へ追随します
  （別の端末や Drive 側で改名されていても、次からは正しい名前で並びます）
- アプリからゴミ箱へ移したファイルは、ピン留めからも自動で外れます

### 改行コードとインデント

**CodeMirror は読み込んだ文字列を `/\r\n?|\n/` で分割し、内部では常に `\n` で扱います。**
そのため何もしないと、CRLF のファイルを開いて保存した時点で LF に変わってしまいます。
読み込み時に元の形式を判定して `tab.eol` に覚え、保存の直前に戻しています。
クライアント側は常に `\n` で扱うので、下書きとの比較もずれません。

インデントは先頭 400 行を見て推定します（タブが優勢ならタブ、
そうでなければ最も多い字下げ幅）。どちらもステータスバーから変更でき、
既存の字下げの一括変換もできます。

### 文字コード（UTF-8 / Shift_JIS）

Excel から書き出した CSV など、日本の現場ではまだ Shift_JIS のファイルが多いので、
**Shift_JIS のファイルもそのまま開いて、Shift_JIS のまま保存します。**

- 読み込み時は、まずバイト列が UTF-8 として厳密に正しいかを見ます（クライアントは
  `TextDecoder('utf-8', {fatal:true})`、サーバーは同じ規則の `utf8Valid_`）。置換文字（U+FFFD）が
  出たかどうかでは決めません。本物の U+FFFD（`EF BF BD`）を含む正しい UTF-8 が、たまたま
  Shift_JIS としても読める並びのときに Shift_JIS と取り違えるためです。
  正しくなければ Shift_JIS として解釈し直し、そちらで正しく読めれば Shift_JIS とみなします
- どちらでもなければ UTF-8 として（壊れた所は置換文字で）開き、読み込み結果に `broken: true` を付けます。
  クライアントはそのタブを閲覧専用にし（`EditorState.readOnly`）、`Api.saveFile` の入口でも保存を止めます
  （比較ビュー・ターミナルからの保存も同じ入口を通るため）
- UTF-8 の BOM は本文から外し、付いていたことを読み込み結果の `bom` で返します。`TextCodec` が
  fileId ごとに覚え、保存時に先頭へ付け直します（ステータスバーは `UTF-8 (BOM)`。メニューで付け外しできます）
- Shift_JIS の中身は Windows-31J（CP932）相当です。ブラウザの `TextDecoder('shift_jis')` と、
  サーバー側の `Windows-31J` を使うので、① や Ⅲ、髙 などの Windows の拡張文字も読み書きできます。
  サーバー側はその実行環境で使える名前を `Windows-31J` → `MS932` → `Shift_JIS` の順に試して決めます
  （最後の `Shift_JIS` は拡張文字を持たないので、① などを含むファイルは保存時の往復確認で止まります）
- 保存時は開いたときの文字コード（と BOM の有無）に戻します。文字コードは fileId ごとに `TextCodec` が覚え、
  `Api.saveFile` がそこから引くので、タブ・比較ビュー・ターミナル（`sed -i`）のどこから
  保存しても同じ文字コードで書かれます
- ブラウザには Shift_JIS の符号化が無いので、デコーダに 2 バイトの全組み合わせを通して
  逆引き表を作ります（初回の保存時に 1 回・数 ms）。規則は WHATWG のエンコーダと同じです
- Mac の IME が入れる「〜」(U+301C) や「−」(U+2212) などは Windows-31J に無いので、
  同じ見た目の「～」(U+FF5E)「－」(U+FF0D) に読み替えて保存します（Windows のメモ帳と同じ挙動）。
  読み直すと読み替えた後の字になります。半角の「¥」「‾」は Shift_JIS の `0x5C` / `0x7E` として保存するので、
  読み直すと `\` / `~` になります（日本語のフォントではどちらも ¥ / ‾ に見えるバイトです）
- REST が途中で失敗して `DriveApp` の経路へ落ちたときは、Shift_JIS のファイルを保存せずに
  失敗として返します（`setContent` は UTF-8 でしか書けず、黙って文字コードが変わるのを防ぐため）
- **Shift_JIS で表せない文字（絵文字・ハングルなど）があると保存を止め**、どの文字が何行目に
  あるかを知らせます。黙って `?` に置き換えることはしません
- ステータスバーの文字コード（`UTF-8` / `UTF-8 (BOM)` / `Shift_JIS`）を押すと切り替えられます。
  切り替えると未保存扱いになり、次の保存からその文字コードで書きます（画面の文字は変わりません）。
  UTF-8 としても Shift_JIS としても読めないファイルは閲覧専用で開き、文字コードも切り替えられません
- 英数字しか入っていない Shift_JIS のファイルは UTF-8 とバイト列が同じなので、UTF-8 として開きます。
  日本語を足して Shift_JIS で残したいときは、保存の前にステータスバーで切り替えてください
- 全体検索と変更履歴（過去の版）の本文も同じ判定で読みます
- GAS 経由の経路で Shift_JIS を書けるのは Drive の REST が使えるときだけです
  （`DriveApp` の `setContent` は UTF-8 でしか書けないため）

#### 既定値と推定の関係

**インデントも改行コードも、本来はファイルの内容そのものです。** そのため
「毎回この値にする」設定にはできません（他人が書いた 4 スペースのファイルを
開いた瞬間に 2 スペースで書き始めたら、流儀が混ざります）。

そこで既定値は **「本文から判定できなかったときに何にするか」** を決めるものとして
扱います。判定できたときはファイル側が勝ちます。

| 場面 | インデント | 改行コード |
|---|---|---|
| 字下げ・改行がある既存ファイル | ファイルから判定 | ファイルから判定 |
| 新規ファイル・一時メモ | **既定値** | **既定値** |
| 字下げが 1 行も無いファイル | **既定値** | — |
| 改行が 1 行も無いファイル（1 行だけ） | — | **既定値** |
| タブ字下げのファイルの**幅** | **既定値** | — |

タブの幅だけ既定値を使うのは、タブ 1 つを何文字ぶんに見せるかが本文からは
決められない（表示上の好みでしかない）ためです。スペースの幅はファイルの
実体なので、判定結果を尊重します。

**常に既定値で開きたい場合は、設定の「インデントをファイルから判定する」を
切ります**（VS Code の `editor.detectIndentation` にあたります）。改行コードは
判定を切れません。既存ファイルの改行コードを既定値で上書きすると、開いただけで
全行が書き換わるためです。

既定値は設定画面のほか、ステータスバーのインデント／改行コードのメニューから
**「この設定を既定にする」**でも変えられます。毎回同じ値に直しているなら、
そこから既定にするのが早いはずです。

### タブ

**仮タブ**: 一覧をシングルクリックすると斜体の仮タブで開き、次のシングルクリックで
同じ枠が入れ替わります。編集するか、ダブルクリックか、右クリックの
「エディタで開く」で固定されます（VS Code と同じ）。タブが無限に増えません。

ドラッグ並べ替え・右クリックメニュー（閉じる / 他を閉じる / 右側を閉じる /
ピン留め / パスをコピー / Drive で開く）に対応しています。
ピン留めしたファイルのタブは「他を閉じる」「右側を閉じる」の対象外です
（ピン留め自体はサイドバーに残る記録です。前述の「ピン留め」を参照）。

**クリップボードはサンドボックス iframe で拒否されることがあります。**
「パスをコピー」が失敗した場合は、内容をモーダルに出して手でコピーできるようにしています。

### 閉じたタブを開き直す

閉じたタブを新しい順に 20 件まで覚えておき、`Alt+Shift+T`（タブの右クリックと
コマンドパレットからも）で開き直します。`Mod+Shift+T` はブラウザが「閉じたブラウザタブを
開き直す」に使っていて奪えないため、`Alt` にしています（macOS の `Option+Shift+T` は `ˇ` の
入力になるので、`ev.key` ではなく `ev.code` で見ています）。

- 覚えるのは Drive 上のファイルを映すタブ（テキストとビューア）だけです。比較・プレビュー・
  ターミナルは実体を持たないので覚えません
- 戻す先は閉じたときのペインの同じ位置です。そのペインが畳まれていれば、いま操作中のペインに開きます
- 仮タブが次のクリックで入れ替わっただけのとき、読み込みに失敗して閉じたとき、
  中身の無い一時メモを片付けたときは覚えません
- ツリーから消えたファイル（ゴミ箱へ移した・他の人が消した）は一覧から外します
- 本文は `Store` に残っていれば 0ms で出ます（残っていなければ普通に読み込みます）。
  覚えているのはこの画面の中だけで、リロードすると消えます

### タブの状態

タブごとに `EditorState` を丸ごと保持するので、切り替えても Undo 履歴・カーソル位置・
複数選択・折りたたみ状態・スクロール位置が保たれます。中クリックでも閉じられます。
未保存のまま閉じようとすると、まず保存を試み、それでも残る場合だけ確認します。

### エディタの分割（ペイン）

エディタ領域を左右・上下に分けて、別のファイルを並べて編集できます。**最大 6 枚**まで、
入れ子にもできます（左半分を上下に割り、その下をさらに左右に、といった形）。

| やりたいこと | 操作 |
|---|---|
| 分割する | `Mod+\`（右へ）/ `Mod+Shift+\`（下へ）。コマンドパレットにもあります |
| 別のファイルを隣に開く | ツリーの右クリック →「横のペインで開く」 |
| タブを別のペインへ移す | タブをドラッグして落とす。**端**に落とすとその向きへ分割、**真ん中**なら移動 |
| 全幅・全高のペインを足す | タブをエディタ領域の**外周**（端から 28px）へ落とす。コマンドパレットにも |
| ペインを選ぶ | `Alt+1` 〜 `Alt+6`、またはそのペインをクリック |
| 大きさを変える | 境目をドラッグ（最小 120px） |
| 閉じる | 中のタブを全部閉じると畳まれます。コマンドパレットの「このペインを閉じる」でも |

プレビューも普通のタブなので、`Mod+Shift+V` で隣のペインに開き、そのまま
ドラッグで好きな位置へ動かせます（「プレビュー」を参照）。

**分割は、選んでいるペインの中で起きます。**「左右に 3 列」を先に作ってから 1 つを
上下に割ると、下段はその列の中にしかできません（`(row (col A B) C D)`）。
上 3 列・下 1 列のように**いまの分割の外側へ足したい**ときは、エディタ領域の外周
（端から 28px）へタブを落としてください。木の根に対して割るので、全幅・全高の
ペインになります（`(col (row A C D) B)`）。コマンドパレットの「全幅のペインを
下に足す」「全高のペインを右に足す」も同じ動きです。かざしている間は、
そのペインではなく**エディタ領域ぜんぶ**に目安が出るので見分けられます。

**同じファイルを 2 つのペインに出すことはできません。** タブは常にどこか 1 つの
ペインにだけ属します。そのぶん `EditorState` はタブが 1 つ持てば済み、
「1 つの文書を複数のビューで共有して同期する」処理が要りません。
VS Code の `Mod+\`（今のファイルを複製して横に置く）とは意味が変わり、
**分割で作られるのは常に空のペイン**です（タブが 2 枚以上あるときは、
表示中のタブがそちらへ移ります）。

#### 持ち方

`Panes` が木を持ちます。葉（leaf）が 1 枚ぶんのエディタ領域、枝（split）が入れ子の分割です。
同じ向きの分割が続くときは枝を深くせず 1 つの枝に並べるので、左右に 3 枚置いても深さは 1 です。

```
(row (col [b.txt, c.js] [d.json]) [a.md])
  左半分を上下に割り、右半分に a.md を置いた状態
```

- 葉は `tabIds`（そのペインに並ぶタブ）・`activeId`（表示中のタブ）・`view`（EditorView）を持つ
- `App.activeId` は「アクティブなペインの表示中タブ」、`Editor.view` は「アクティブな
  ペインの EditorView」への getter。分割前から書いてある「アクティブかどうか」の
  判定は、そのまま意味が通る
- 特定のタブに効かせたい処理（配色・折り返しの差し替えなど）は `Panes.viewOf(tabId)` を使う。
  アクティブでないペインに出ているタブにも届く必要があるため

タブバー・パンくず・Markdown の入力バー・埋め込みビューア・比較ビューは**ペインごとに
1 組**持ちます（`index.html` の `<template id="tplPaneLeaf">` を複製）。
ステータスバーだけはアプリ全体で 1 本のままで、アクティブなペインの状態を映します。

`getTab(id)` は id が空なら必ず `null` を返します。タブの `aliasId`（作成中の一時メモの
仮 ID）は既定が `null` なので、`getTab(null)` を素通しすると「`aliasId` が `null` の
タブ」＝先頭のタブに当たり、**空のペインの状態を無関係なファイルへ書き戻す**事故になります。

#### 大きさ

取り分は `flex-grow` で持たせ、境目のドラッグでは**掴んだ境目の両隣だけ**を動かします
（他のペインの大きさは変わりません）。分割で枚数が増えたときは、その枝の中を均等に
配り直します。分割元が半分ずつ譲っていく方式だと、3 枚目・4 枚目がみるみる細くなって
使いものにならないためです。

DOM は木の形どおりに組み直しますが、**既にその位置にある要素は動かしません**。
ビューアや HTML プレビューの iframe は DOM から外して入れ直すと読み込み直しになるので、
分割で親が変わるペイン以外は触らないようにしています。

#### 起動時

セッションには「どのタブがどのペインにいたか」と取り分だけを記録します。
起動時に本文を読むのは**アクティブなペインの 1 枚だけ**で、残りのペインは
最初の描画が終わったあとに `paintOtherPanes()` が順に読み込みます。
全ペインぶんの本文を `doGet` のスナップショットに載せると HTML が膨らみ、
その場で描ける速さ（「キャッシュ」を参照）が落ちるためです。

### 共有ドライブ

フォルダ選択画面には「マイドライブ」と、ユーザーが参加している共有ドライブが
並びます。共有ドライブの列挙は `DriveApp` ではできないため `Drive.Drives.list` を
使います（拡張サービスが使えない場合はマイドライブだけを出し、共有ドライブは
URL 貼り付けで指定してもらいます）。

**共有ドライブの最上位フォルダは、フォルダ ID がドライブ ID と同じ**です。
この ID は `DriveApp.getFolderById()` から開けないことがあるため、
アクセス検証を 2 種類に分けています。

| 用途 | 関数 | 挙動 |
|---|---|---|
| 読み取り（一覧・基準フォルダの検証） | `assertFolderAccess_` | `DriveApp` で開ければそれを返し、開けなくても Drive API から見えていれば ID と名前だけで先に進む |
| 書き込み（作成・移動・改名・削除） | `assertFolder_` | `DriveApp` の `Folder` が必要なので、開けなければエラー |

一覧の取得自体は Drive API が担当するので、読み取り側は `Folder`
オブジェクトが無くても成立します。パンくずだけは親を辿る必要があるため、
`Folder` が取れない場合は自分自身の 1 段だけになります。

#### ドライブ名は `DriveApp` からは取れない

**共有ドライブの最上位は、`DriveApp` からも Drive API の `Files` からも
実際のドライブ名が取れません。** ロケール依存の汎用名（日本語なら「ドライブ」）が
返るため、そのまま使うと共有ドライブのルートが全部「ドライブ」になり、
複数開いていると見分けがつかなくなります。実名が取れるのは `Drive.Drives` だけです。

そのため `sharedDriveNames_()` で id → name の対応表を作り、
`displayFolderName_()` がルート名を差し替えます。対応表に無い ID
（＝通常のフォルダ）は渡された名前をそのまま返すので、共有ドライブを
使っていない環境の挙動は変わりません。

ルート 1 件ずつ `Drives.get` を叩くとルートの数だけ往復するので、
`Drives.list` の 1 リクエストでまとめて取り、`CacheService` に 30 分載せます。
この関数はフォルダを開くたびに通るため、**取得に失敗した場合も 5 分だけ
覚えておきます**。失敗をキャッシュしないと、失敗し続ける API 呼び出しを
毎回繰り返してアプリ全体が遅くなるためです。

差し替えは `assertFolderAccess_` と `breadcrumb_` の 2 箇所だけで、
ルート名は必ずここを通ります。既存ユーザーの `UserProperties` に
「ドライブ」が保存されていても、`getBootstrap` の名前更新
（`nameChanged`）が次回起動時に正しい名前へ直します。

共有ドライブの**最上位**での新規作成・移動は、Drive 側の設定によって
制限されている場合があります。その場合は理由を添えたエラーを返すので、
1 つ下のフォルダを対象にしてください。

### 複数フォルダ（マルチルート）

ツリーの最上位に複数のフォルダを並べられます。マイドライブのフォルダと
共有ドライブのフォルダを混ぜても構いません。最大 8 個（`MAX_ROOTS`）。

設定は `UserProperties` の `roots` に `[{id, name}, ...]` として保存します。
単一フォルダだった時代の `baseFolderId` が残っている場合は、初回読み込み時に
1 件の配列へ移行して旧キーを消します。

**フォルダの追加はタブを閉じません。** 追加はツリーが増えるだけなので、
編集中のファイルはそのまま続けられます。フォルダを外したときは、
そのフォルダ配下で開いていたタブだけを閉じます（未保存なら確認します）。

起動時は、全ルートと展開されていたフォルダの中身を
`listEntriesMany_` で **1 リクエストにまとめて**取得します。
ルートが増えても起動時の往復は 1 回のままです。

**ルートをまたぐ移動には確認を出します。** 別ドライブへ移すと所有者が
変わる可能性があるためです（共有ドライブへ移すとファイルの所有者が
共有ドライブになります）。ルートの中だけで完結する移動は確認なしで実行します。

ルート行自体はドラッグできません（ツリーの土台なので）。外すのは
右クリックの「このフォルダを閉じる」か「フォルダを管理」からです。
ルートフォルダの名前変更・ゴミ箱への移動はメニューに出していません
（Drive 側で操作してください）。

ツリーの余白へのドロップは、どのルートが対象か曖昧になるため無効です。
フォルダ行に落としてください。

### フォルダツリー

各ルートより上には遡りません（別の場所を見るにはヘッダーの「フォルダを管理」から
追加します）。ノードはフラットな `Map` で保持し、描画時に再帰的に並べ直しています。
ネストした DOM にしていないのは、ドラッグ＆ドロップと絞り込みの扱いが
単純になるためです。

展開は 1 階層ずつの遅延ロードです。「子フォルダを持つか」は事前に調べません。
調べるとフォルダ数ぶんの API 呼び出し（N+1）が発生して遅延ロードの意味が無くなるため、
すべてのフォルダを展開可能として描画し、開いて空だったときに知らせます。

絞り込みは**読み込み済みの階層だけ**が対象です。未展開のフォルダの中までは検索しません
（全階層を走査するとフォルダ数ぶんの往復が必要になるため）。

### インライン編集

改名と新規作成は**行の上で直接編集**します（VS Code と同じ）。
以前はモーダルでしたが、それが一番 VS Code から遠い部分でした。

確定は Enter、取り消しは Escape、フォーカスを外しても確定します。
**サーバー側で弾かれた場合は入力行を残し**、名前を直して再挑戦できるようにしています
（重複名・使えない拡張子など）。

### ツリーのキーボード操作

ツリー（`#entryList`）は `tabindex="0"` でフォーカスを受け取ります。
`↑↓` 移動、`→` 展開・子へ、`←` 折りたたみ・親へ、`Enter` 開く（固定タブ）、
`Space` 仮タブで開く、`F2` 改名、`Delete` ゴミ箱、`Alt+N` 新規ファイル。

キーボードカーソルの枠は**ツリーにフォーカスがあるときだけ**表示します。

### 全体検索

`Mod+Shift+F`（CodeMirror の検索パネル `Mod+F` とは別物）。三段構えです。

1. ルート配下のフォルダ ID を階層ごとに列挙する
2. Drive の全文索引（`fullText contains`）で候補ファイルを絞る
3. 候補のうち上位 30 件だけ本文を取り、一致行と行番号を組み立てる

全ファイルを読んで検索すると往復もダウンロード量も跳ねるので、候補の絞り込みは
Drive 側の索引に任せています。

#### 手元にある本文は先に、ブラウザの中で探す

Drive の索引には弱点が 2 つあります。**保存した直後の内容が載っていないこと**と、
**語の途中では当たらないこと**です。そこで、手元にある本文（開いているタブと、
`Store` に残っている最近読んだファイル）はブラウザの中で文字列として探し、
Drive の結果を待たずに先に出します。開いているタブは画面に出ている中身を見るので、
**未保存の内容でも当たります**（結果に「未保存」の印が付きます）。

Drive の結果が届いたら合わせて出し直します。同じファイルが両方にあるときの扱いは次のとおりです。

- 開いているタブは手元の結果を使います（画面の中身が一番新しいため）
- `Store` にだけある本文は、Drive 側の更新日時のほうが新しければ Drive の結果を使います
- 手元の本文（Drive と同じか新しいもの）では当たらないのに Drive では当たったファイルは、
  索引が古い（保存で消した語が残っている）とみなして出しません

手元の探索もルート配下のファイルだけが対象です（ツリーか索引でルートの中にあると分かるもの）。

#### なぜ先にフォルダを列挙するのか

Drive の検索条件には **`X in parents`（直下のみ）しか無く、「配下すべて」を表す書き方が
ありません**。ルート ID だけを親にすると *ルート直下のファイルしか当たらず*、1 段でも
掘った先は永久に出てきません。`日報 / 2026 / 09 / 20260911_作業日報.txt` のように
年月でフォルダを切っていると、**何を打っても 0 件**になります。

そこで検索の前に、ルートから階層を 1 段ずつ広げてフォルダ ID を集めます。段ごとに
まとめて（REST 経路なら `fetchAll` で並列に）問い合わせるので、**往復はフォルダの数ではなく
階層の深さで決まります**。列挙の結果はブラウザ側で 60 秒だけ使い回すので、検索語を
打ち直すたびに階層を辿り直すことはありません（フォルダを作る・移す・捨てるといつでも捨てます）。

集めた ID は 1 本のクエリに入り切らないので分割して投げます。1 本あたりの親の数は
URL 長の上限（2,082 文字）から逆算していて、検索語が長いほど少なくなります。

#### 制約

- **索引の反映が遅れるので、保存直後の内容は見つからないことがあります**
  （開いている・最近開いたファイルなら、上の手元の探索で見つかります）
- **正規表現は使えません**。索引は語単位なので、**語の途中だけでも当たりません**
  （「ルーティン」は当たりますが「ーティ」は当たりません。手元にある本文は語の途中でも当たります）
- 検索語は 2 〜 100 文字
- フォルダは深さ 8 段・のべ 300 個まで。打ち切ったときは結果の下に「範囲が広いため一部まで」と出ます

結果の行をクリックすると、そのファイルを開いて該当行へカーソルを移します。
サイドバー下端には「フォルダ N 個を検索」と出るので、0 件のときに
*範囲が足りないのか・索引に無いのか* を切り分けられます。

### 変更履歴（Drive のリビジョン）

`Drive.Revisions.list` で過去の版を一覧します。VS Code のタイムライン相当で、
**このエディタのセッションを超えた Undo** として使えます。

版を選んでも **Drive 上のファイルは書き換えません**。中身をエディタに読み込むだけなので、
その状態で保存すれば結果的に復元になり、競合検出も通常どおり働きます。
共有ドライブや権限の設定によっては参照できないことがあります。

行の右端の ⇄ ボタンで、その版と**いまの内容を並べて比べられます**（読み込みません）。

### 比較（WinMerge 相当）

差分の計算と描画は CodeMirror 公式の `@codemirror/merge` に任せています。
**比較タブ**（`kind:'diff'`）は本文を持たない独立したタブで、保存・言語モード・
プレビュー・自動保存といったテキストタブ向けの処理はすべて素通りします。

**比べる材料（`DiffSide`）はファイルであることを前提にしていません。**
左右それぞれ、次のどれでも選べます（バー上部のチップを押すとメニューが出ます）。

| 種類 | 中身 | 書き戻せる先 |
|---|---|---|
| `file` | Drive 上の保存済み内容 | Drive（競合検出あり） |
| `buffer` | 開いているタブの編集中の内容（未保存を含む） | そのタブ |
| `revision` | Drive のリビジョン（過去の版） | なし |
| `text` | 貼り付けた文字列（Drive 上に実体が無い） | なし |
| `empty` | 空 | なし |

そのため「ファイルとファイル」だけでなく、**貼り付けた文字列同士**、
**片方はファイル・片方は貼り付け**、**同じファイルの編集中と保存済み**、
**同じファイルの過去の版と現在**、といった組み合わせが同じ画面で扱えます。
どの側も編集でき、書き戻す先がある側（`file` / `buffer`）は
その場で保存・反映できます。行き先が無い側は「新しいファイルに保存…」で
書き出せます（保存できたらその側は `file` に切り替わり、次からは普通に保存できます）。

`buffer` 側をタブへ反映したとき、もう片側が**同じファイルの `file`**（Drive 上の内容）なら、
タブの基準日時（`baseUpdatedAtIso`）をその `file` 側の更新日時へ進め、競合の印も外します。
保存の競合から「差分を見る」で開いて決めた内容は、その版を見たうえでの結果だからです
（進めないと、反映した直後の自動保存がまた競合になります）。進めるのは比べた版の日時だけで、
比較を開いたあとに別の人が保存していれば次の保存は従来どおり競合になります。
タブの基準のほうが新しいとき（比較を開いたあとにタブを保存した）は戻しません。

**表示は 2 通り。**

- **並列**（`MergeView`）… 左右に並べ、同じ行を縦に揃えます。外側 1 つが
  スクロール領域なので、左右がずれることが構造上ありません。
  中央の矢印でブロック単位にコピーできます（向きは「左 → 右」ボタンで反転）
- **インライン**（`unifiedMergeView`）… 1 つの画面に元の行をウィジェットで重ね、
  ブロックごとに「取り込む／戻す」を出します

共通の操作として、**同じ行を畳む**（変更の周り 3 行だけ残す）、
**空白を無視**（行の前後と行内の空白・空行の違いを無視）、
`F7` / `Shift+F7` での差分送り、`N 箇所 / −X 行 / +Y 行` の集計があります。

改行コードの違いは差分に出ません（本文はエディタへ渡す前に必ず `\n` にそろえ、
保存時に元の形式へ戻すため）。

**「空白を無視」は表示も整形後の内容になります**（`@codemirror/merge` は
比較用と表示用のテキストを分けられないため）。そのあいだは両側を閲覧専用にし、
書き戻しも止めています。元の文字列で編集したいときは、このトグルを切ってください。

入口は次のとおりです。

| どこから | 何と何を比べるか |
|---|---|
| コマンドパレット「比較ビューを開く」 | 空。左右はあとから選ぶ（貼り付けでもよい） |
| コマンドパレット「Drive 上の内容と比較」 | Drive 上の保存済み内容 ⇄ 編集中の内容 |
| コマンドパレット「過去の版と比較…」 | 選んだ版 ⇄ いまの内容 |
| ツリーで 2 件選んで右クリック | その 2 ファイル |
| ツリーのファイルを右クリック | 別のファイル / 貼り付けたテキスト / 過去の版 |
| タブを右クリック | Drive 上の内容 / 他のファイル / 過去の版 |
| 変更履歴パネルの ⇄ ボタン | その版 ⇄ いまの内容 |
| 保存の競合ダイアログ「差分を見る」 | Drive 側 ⇄ 手元の編集内容 |

比較タブは**セッションに記録しません**。貼り付けた文字列や過去の版は Drive 上に
実体が無く、リロード後に同じものを組み立て直せないためです（開いていた
テキストのタブはこれまでどおり復元されます）。

### ターミナル

`Ctrl+\`` か `Mod+Alt+T`、コマンドパレット、フォルダの右クリック（「ここでターミナルを開く」）
で開きます。置き場所は**画面いちばん下の全幅の段**で、2 枚目からは同じペインにタブで並びます。

本物のシェルではありません。Apps Script の Web アプリにプロセスは無く、
`bash` も `git` も動きません。ここで動くのは `TERM_COMMANDS` に定義したコマンドだけです。
それでも GUI では届かない次の 3 つを埋められます。

1. **まとめて動かす** — `mv *.md docs/`、`sed -i 's/旧/新/g' **/*.md`
2. **引数を渡す** — `open client/app/270-tabs.js:120`、`diff a.md b.md`
3. **同じ操作を繰り返す** — `↑` で履歴（`localStorage` に 200 件）

#### タブの一種として作ってある

`kind:'term'` のタブで、DOM（出力と入力欄）は**タブが持ちます**。ペインへは差し込むだけなので、
分割・ドラッグでの移動・セッション復元がプレビューや比較ビューと同じ仕組みでそのまま効きます。
`EditorView` を使わないため、`activateTab` はターミナルのときだけ CodeMirror の到着を待ちません
（CDN に届かないときこそ開きたい画面なので、ここで止めない）。

セッションに残すのは**いたフォルダだけ**（`cwd`）です。出力は残しません。
サーバー側は `SESSION_KINDS` に `term` を足し、`validTabId_` が `term:<通し番号>` を
通すようにしてあります（これが無いと合成 ID がペインの記録から落ちます）。

#### パスの決まりごと

| 書き方 | 指すもの |
|---|---|
| `/` | 仮想ルート。直下にルートフォルダと「一時メモ」が並ぶ |
| `~` | 一時メモ |
| `.` / `..` | いまのフォルダ / 親 |
| `*` `?` `[abc]` | 1 階層の中で当たる |
| `**` | 階層をまたいで当たる（`**/*.md`） |
| `id:<Drive の ID>` | 名前に `/` を含むファイルを指すための逃げ道 |
| `%` / `%sel` | 編集中のファイルの全体 / 選択範囲（読むのにも書くのにも使える） |

**Drive ならではの制約が 4 つあります。**

- **名前に `/` が入れられる。** パスで書けないファイルが存在しうるので、`id:` を用意しています
- **同じフォルダに同名のファイルを置ける。** パスが一意の識別子になりません。コマンドは
  解決した時点でファイル ID を掴み、以降は ID で動きます
- **名前に空白が普通に入る。** 引用符（`'` `"`）とバックスラッシュで囲みます。
  補完は必要なら自動でくるみます
- **ルートが複数ある。** `/` は一意ではないので、ルート名を第 1 階層として扱います

#### コマンド

`help` で一覧、`help <名前>` で使い方が出ます。

| 分類 | コマンド |
|---|---|
| 移動・一覧 | `pwd` `cd` `ls [-l]` `tree [-L n]` `find [-name] [-type]` `refresh` |
| ファイル操作 | `mkdir [-p]` `touch` `cp` `mv` `rm [-r] [-f]` |
| 中身 | `cat` `head [-n]` `tail [-n]` `wc [-lwc]` `sort [-r -u -n]` `uniq [-c]` `echo` |
| 検索・置換 | `grep [-i -F -r -l -c]` `sed [-i]` |
| エディタ | `open [-s]` `diff` `rev` `split` `theme` `save` `pin` |
| その他 | `help` `history` `clear` |

別名は `ll`（= `ls -l`）`dir` `md` `del` `man` `?` です。

パイプ（`|`）とリダイレクト（`>` `>>`）が使えます。`<` はありません（`cat` で足ります）。

`sed` の置き換える側は sed の書き方です。`&` が一致した全体、`\1`〜`\9` が `( )` の中身、
`\&` `\\` `\n` が文字どおりの `&`・`\`・改行です。`$` は特別扱いしません（JS の `$1` `$&` は効きません）。
探す側は JavaScript の正規表現です（`\d`、`(?:…)`、`+` などがそのまま使えます）。

#### 壊す操作の前には必ず止まる

`rm`、`sed -i`、中身のあるファイルへの `>` は、**何がどうなるかを先に出してから** `[y/N]` を聞きます。
`sed -i` は聞く前に全ファイルを読んで置換を試し、「5 ファイル・6 箇所」と内訳を出します。
つまり確認の材料そのものが空振りでない証拠になります（0 件ならそもそも聞かずに終わります）。

`rm` は Drive のゴミ箱へ入れるだけなので、あとから戻せます。`-f` を付けると確認を飛ばします。
ただし**未保存の編集があるタブが対象に含まれていれば、`-f` でも中止します**。ファイルはゴミ箱から
戻せても、閉じたタブの未保存の編集はどこにも残らないためです（`-f` を外せば、確認のうえで破棄できます）。

`grep` と `sed` は、読めなかったファイル（権限・バイナリなど）を飛ばしますが、黙っては飛ばしません。
`grep` は件数を、`sed` は確認と結果にファイル名を添えます（「全部置換できた」ように見えないように）。

#### 編集中のバッファを通す（`%` と `!`）

`%` は「最後に表示していたテキストのタブ」（`App.lastTextTabId`）を指します。
ターミナルへフォーカスを移しても、さっきまで編集していたファイルを指し続けます。

```
cat %sel | sort > %sel     選択範囲を並べ替えて置き換える
!sort                      同じことの短い書き方（Vim の ! と同じ）
cat % | grep TODO          いま編集中の中身から TODO を拾う
```

`!` で始まる行は `cat %sel | … > %sel` に展開されます。書き戻しは**1 つの
トランザクション**として流すので、気に入らなければ `Mod+Z` で元に戻せます。

#### 書き込みは既存の保存経路に乗せる

`>` や `sed -i` の書き込み先が**開いているタブなら、そのタブ越しに書きます**
（`termWriteFile`）。`doSave` を通るので競合検出・キャッシュ更新・下書きの後始末が
そのまま効き、画面に出ている内容と Drive の中身がずれません。
**未保存の編集があるファイルには触りません**（そのファイルだけ飛ばして理由を出します）。

閉じているファイルは `Store` の更新日時を基準に `saveFile` します。改行コードは
読んだときの形（CRLF/LF）に戻して書きます。画面へ出す出力は末尾の改行を付けませんが、
**ファイルにするときは付けます**（改行で終わらないテキストファイルは、次の追記で行が混ざるため）。

#### 補完（`Tab`）

候補は基本的にツリー（`Tree.nodes`）から**同期で**作ります。読み込み済みの階層なら
サーバー往復ゼロで、押した瞬間に出ます。未読込のフォルダをまたぐときだけ 1 往復
（`listEntriesMulti`）で、`cd` の直後にその中身を先読みしておくのでほとんど当たりません。

| 位置 | 候補 |
|---|---|
| 1 語目 | コマンド名と別名（説明つき） |
| `-` で始める | そのコマンドのオプション |
| 2 語目以降 | コマンドごとに `path` / `dir` / `file` / 固定の語 |
| `>` の直後 | パス |
| `%` で始める | `%` と `%sel` |

**日本語のファイル名では「共通する頭を伸ばす」がほとんど効きません**
（「議事録_2026」と「会議メモ」に共通の頭は無い）。そこで

- 伸ばせるとき（英数字）は bash と同じくそこまで一気に伸ばす
- 伸ばせないときは**一覧を出して `Tab` で送っていく**（`Shift+Tab` で戻る）

の二段構えにしています。前方一致で候補が無ければ部分一致でも拾います
（日本語の名前は中ほどを覚えていることが多いため）。

**IME の変換中は `Tab` も `Enter` も奪いません**（`ev.isComposing` と
`compositionstart/end` の両方を見る）。変換の確定に使われるキーなので、
ここを奪うと日本語のファイル名が打てなくなります。

#### 速さのために決めていること

- **出力は 1 コマンド 1 ブロック**。`white-space: pre-wrap` の `div` 1 枚に
  `textContent` で流し込み、行ごとに要素を作りません。クリックできる行
  （`ls` `find` `grep`）だけ `button` にします
- 出力は 240 ブロックまで。古いものから捨てます。1 回の表示は 2000 行までで、
  超えた分は「あと N 行は省略しました」に畳みます
- フォルダの一覧は `listEntriesMulti` で**まとめて 1 往復**。`**` の展開でも
  1 階層ぶんを 1 本にします（上限 400 フォルダ・2000 件）
- 本文は `Store`（LRU + 再検証）を通すので、開いているファイルは 0ms。
  `grep` と `sed -i` は対象をまず `readFilesMulti` で 20 件ずつまとめ読みします
- 書き込みは 6 本まで並列（Drive の PATCH は 1 本 2.5 秒前後で、直列だと待てない）
- 長い処理は `Ctrl+C` で止まります（各コマンドがループの中で `ctx.check()` を見る）

### 設定

`UserProperties` の `settings` に保存します。**クライアントから来た値は
サーバー側で型と範囲へ丸めます**（`sanitizeSettings_`）。既定値の定義は
サーバー側の `defaultSettings_()` が正で、クライアントは同じ値を
フォールバックとして持つだけです。

自動保存を切ると `Mod+S` でだけ保存します（下書きは切っていても localStorage に残ります）。

一時メモ関係では「置き場所」「形式（`.txt` / `.md`）」
「残す期間（既定 30 日・`0` で無期限）」「いま片付ける」の 4 つを置いています。
**置き場所だけは `settings` に入れず**、専用のキー（`tmpParent`）に持ちます。
値が Drive の実体と結びついていて、変更が「フォルダを作る・中身を移す」という
副作用を伴うので、他の設定と同じ「送ったら丸めて保存するだけ」の経路には乗せられないためです。

インデントと改行コードの既定値もここです（`detectIndentation` /
`defaultIndentWithTabs` / `defaultIndentUnit` / `defaultEol`）。
意味は「改行コードとインデント」の節を参照してください。

プレビュー関係では「左右のスクロール連動（`previewScrollSync`）」と
「Markdown の入力バー（`mdToolbar`）」を置いています。分割幅（`previewSplit`）は
仕切りをドラッグした時点で保存されます。

配色は「外観（`themeMode`）」です。`system` / `light` / `dark` の 3 つで、既定は `system`。
詳しくは「配色」の節を参照してください。

### 複数選択

`Cmd/Ctrl` クリックで追加・解除、`Shift` クリックで範囲選択（画面の並び順）、
`Cmd/Ctrl+A` で全選択、`Shift+↑↓` でキーボードから範囲を伸ばせます。
複数選択中は右クリックメニューが一括操作に切り替わり、D&D も選択した全部が動きます。
ルートフォルダは一括操作の対象から除きます。

### OS からのアップロード

ファイルをフォルダ行にドロップすると Drive に作成します。
**テキストもバイナリも Base64 で送り**、サーバー側で Blob として作ります。
文字コードの解釈をクライアントでやらずに済み、PDF や画像も同じ経路で扱えます。

上限は 1 件 2MB です。Base64 で 4/3 に膨らんだものが `google.script.run` の
リクエストとして飛ぶため、編集の上限（5MB）より小さく取っています。
同名のファイルは**上書きせず**「… のコピー」に退避します。

ツリー余白へのドロップはルートが 1 つのときだけ受けます（複数あると
どこへ入れるか決められないため）。ウィンドウ全体では `dragover` / `drop` を
打ち消して、ブラウザがファイルを開いてしまうのを防いでいます。

### ドラッグ＆ドロップ

ファイル／フォルダをフォルダ行に落とすと移動します。ファイル行に落とした場合は
その親フォルダへ移動します（VS Code と同じ挙動）。

自分の子孫へのフォルダ移動は、クライアント側で弾いたうえで、サーバー側でも
親を遡って再判定しています（ツリーに載っていない階層があるため）。

### 埋め込みビューア

Drive / Docs が出しているプレビュー URL を iframe に入れるだけの閲覧専用です。
本文を取得しないので 5MB 制限の対象外で、`readFile` も呼びません。
埋め込みが拒否された場合に備えて、上部に別タブで開くリンクを常設しています。

| 種別 | kind | URL |
|---|---|---|
| PDF | `pdf` | `drive.google.com/file/d/<id>/preview` |
| 画像・音声・動画・Office | `media` | 同上 |
| Google ドキュメント | `doc` | `docs.google.com/document/d/<id>/preview` |
| Google スプレッドシート | `sheet` | `docs.google.com/spreadsheets/d/<id>/preview` |
| Google スライド | `slide` | `docs.google.com/presentation/d/<id>/preview` |
| Google 図形描画 | `drawing` | `docs.google.com/drawings/d/<id>/preview` |

**編集はできません。** iframe の中で編集させることは Drive 側の仕様上できないので、
編集したいときは上部のリンクから本家を開きます。

判定は `DriveService.gs` の `classifyMeta_` 1 箇所に集めてあり、`viewer: 'embed'` を
返したものがこの経路に入ります。クライアント側の対応表は `client/app/270-tabs.js` の `VIEWERS` で、
URL・アイコン・表示名・リンクの文言をここだけで持っています。

`.drawio.png` / `.drawio.svg`（drawio が XML を埋めて書き出す画像）は、
テキストではなく画像として開きます。図として見たいファイルだからです。

閲覧専用のタブでは、変更履歴は出しません（読み込んでもエディタに戻せないため）。

### プレビュー（Markdown / HTML / drawio / 表）

`.md`、`.html`（`.htm` `.xhtml` `.vue` `.svelte` を含む）、`.drawio`、`.csv` / `.tsv` でステータスバーに
プレビューボタンが出ます。`Mod+Shift+V` でも開け閉めできます。
いずれも入力が止まったら自動で描き直します（Markdown は 250ms、HTML と drawio は
再読み込み・図の描き直しになるため 600ms 待ちます）。

**プレビューは独立したタブです。** `Mod+Shift+V`（またはステータスバーのボタン）で
隣のペインに開き、タブなのでドラッグで好きな位置へ動かせます。上下に置く、
3 枚目のファイルの隣に並べる、といったことが普通のタブと同じようにできます。

| | |
|---|---|
| タブ | `preview:<元のファイル ID>`。「見る」のバッジが付く |
| 中身 | `tab.pv` が DOM（本文・iframe 2 つ・案内）と描画の状態を持つ |
| 元ファイル | `tab.pv.src`。本文はそのタブの `EditorState` から読む |
| 閉じるとき | 元のファイルを閉じると、映すものが無くなるので一緒に閉じる |

複数のファイルのプレビューを同時に開けます。DOM と描画状態はタブごとに持つので、
ペインを移してもスクロール位置も描いた図もそのまま引っ越します。

隠れているプレビューは描き直しません（`pv.painted` を落としておき、次に表示された
ときにまとめて描く）。編集のたびに見えていないものまで作り直すのは無駄で、
Mermaid の図があると特に重くなるためです。

#### Markdown

`marked` で HTML 化し、`DOMPurify` でサニタイズしてから描画します。
**ファイルの中身をそのまま HTML として描画するため、サニタイズは必須です**
（自分のドライブのファイルでも、他人から共有されたものを開く可能性があります）。
両ライブラリは初回プレビュー時に遅延読み込みします。

描く先はアプリ本体の DOM なので、DOMPurify の HTML プロファイルに加えて次を行っています。

- `<style>` と、送信先を持てる部品（`<form>` `<textarea>` `<select>` `<button>`）を落とす（`MD_PURIFY`）。
  `<style>` は画面全体に効くので、共有された .md がアプリの UI を隠したり偽装したりできてしまう
- プレビュー本体に `contain: layout` と `isolation: isolate` を付け、`position: fixed` や大きな
  `z-index` がプレビューの外（タブバー・ダイアログ）に重ならないようにする
- **外部の画像・動画・音声と、`url()` を含む `style` 属性は既定で止める。** 開いただけで
  相手に「読んだこと」が伝わる（トラッキング画像）ためです。上端のバーの［表示する］で、
  そのプレビューに限って出せます。止めるのは `data:` / `blob:` 以外の URL すべてです。
  HTML はいったん `<template>` に入れてから URL を外すので、止めている画像への通信は一度も起きません

#### スクロール連動

エディタとプレビューのスクロール位置をそろえます（設定で切れます）。

行とピクセルを直接対応させると、見出し・表・コードブロックで 1 行あたりの
高さが変わるため合いません。そこで **ブロックごとの対応表**を作っています。

1. `marked.lexer()` でトークンに分け、`raw` の改行数を数えて各ブロックの開始行を出す
   （marked のトークンは行番号を持たないため）
2. トークンを 1 つずつ `marked.parser()` に渡し、出力の先頭タグへ `data-src-line` を足す
3. 描画後に各要素の位置を測り、「元の行 ↔ プレビュー上の位置」の対応表にする
4. あいだは線形補間する

参照リンク（`[a][ref]`）はトークンを分けても壊れません。インラインの解決は
`lexer()` の時点で終わっているためです。

追従の向きは「最後に動かした側が親」で、`Sync.lock` により 150ms は逆向きの
追従を無視します。これが無いと、追従した側のスクロールイベントが戻ってきて
互いに引っぱり合います。

#### Mermaid の図

` ```mermaid ` のコードブロックを `mermaid` で SVG に差し替えます。
mermaid は数 MB あるので、**そのブロックが実際に現れるまで読み込みません**。

書いている途中の図は構文エラーになるのが普通なので、

- 同じソースの図は SVG をキャッシュして描き直さない（打鍵のたびに再描画しない）
- 解釈できなかったときは、直前に描けた図を薄く表示したままにする

ようにしています。ラベル内の HTML は mermaid 側の `securityLevel: 'strict'` で
エスケープされますが、mermaid には過去に XSS が何度も見つかっているので、出力の SVG にも
`DOMPurify` を通しています（`MERMAID_PURIFY`）。図の色を決める SVG 内の `<style>` と、
ラベルを描く `foreignObject` 内の HTML は残す設定なので、見た目は変わりません。

残した `<style>` はアプリ本体の文書に入るので、そのままだと**図から画面全体の CSS を書き換えられます**
（タブバーやダイアログの偽装、`url()` や `@import` で「開いたこと」を外へ伝える）。そこで 2 段で止めています。

- `%%{init: ...}%%` や frontmatter の `config:` から、CSS へ入る項目を書き換えられないようにする
  （`secure` に `themeCSS`・`themeVariables`・`fontFamily`・`altFontFamily`・図ごとの `*FontFamily` を追加。`MERMAID_SECURE`）
- DOMPurify のあと、`<style>` の中身を `scopeMermaidCss` で絞る。残すのは、セレクタがすべて
  その SVG の `#id` で始まり兄弟（`~` `+`）へ出ない規則と、その規則を入れた `@media` / `@supports`、
  mermaid 自身の `@keyframes`（`dash` など）だけ。宣言からは `url()`（図の中を指す `url(#…)` は除く）・
  `image-set()`・`expression()`・`\` エスケープを含むものを落とし、`@import`・`@font-face` などの
  それ以外の `@` 規則と入れ子の規則も落とします。基準の id は、一番外側の SVG がこちらの付けた形
  （`mmd-世代-番号-長さ`）のときだけ使い、合わなければ `<style>` ごと外します

図の中の外部の画像（`<image href>` など）は、Markdown の画像と同じく `holdRemote` で止め、
上端のバーの［表示する］で出します。mermaid 自身の出力は全種類・全テーマで、`url(` に `#` の付いていない
1 か所（状態図の neo のグラデーション。もともと効いていない）を除いて削られないことを確かめています。

#### HTML

**サニタイズせず、`sandbox` 付き iframe の `srcdoc` へまるごと渡します。**
`<script>` や `<style>` を落としたらプレビューになりません。そこで
「消す」のではなく「隔離する」方針を取っています。

`allow-same-origin` を付けないのが要点です。これが無い限り中身は opaque origin に
なり、親の DOM も、このアプリが持っている Drive のセッションも触れません。

**スクリプトは既定で止めています**（`sandbox=""`。スクリプト・フォーム・ポップアップ無し）。
共有された HTML を開いただけで、外部への送信・偽のログインフォーム・ポップアップが動かないようにするためです。
上端のバーの［スクリプトを実行する］を押すと、そのプレビューに限って
`allow-scripts allow-modals allow-forms allow-popups` に切り替えて読み込み直します。

srcdoc を入れ替えると iframe は毎回読み込み直しになり、表示が先頭へ戻ります。
中身から `scrollY` を読むことはできない（opaque origin）ので、プレビューへ渡す
文字列の末尾に小さなスクリプトを足し、`postMessage` で縦位置を知らせて
次の描画で戻しています。足すのはプレビュー用の文字列だけで、保存される本文は
変わりません（スクリプトを止めている間はこの仕組みも動かないので、描き直すと先頭へ戻ります）。
親が受け取るのは送り主が `'null'`（sandbox の opaque origin）のメッセージだけです。
drawio も同様に、図の XML を送る宛先と、受け取るメッセージの送り主を `https://embed.diagrams.net` に固定しています。

想定しているのは **1 ファイルで完結する HTML** です。`<img src="./a.png">` や
`<link href="style.css">` のような相対パスは、隣に置いた Drive のファイルを
指していても解決できません（Drive はファイルを HTTP のパスとして配信しないため）。
CDN などの絶対 URL は読み込めます。

#### drawio

`.drawio` / `.dio` / `.drawio.xml` は**中身が XML のテキストファイル**なので、
エディタで開いて編集できます。図としての表示はプレビュー側で行います。

`embed.diagrams.net` を iframe に出し、`postMessage` で XML を渡して描かせます
（`Drawio.load`）。やり取りは JSON 文字列で、iframe から `{"event":"init"}` が
届いてから `{"action":"load","xml":…}` を送る、という順番です。URL の
フラグメントに図を載せる方式（`#R…`）もありますが、更新のたびに iframe を
読み込み直すことになるので採っていません。

`chrome=0` を付けているので**読み取り専用**です。ここから Drive へ書き戻すことは
ありません。図を直したいときは、エディタ側の XML を編集するか drawio 本体で開きます。

15 秒待っても `init` が来なければ、案内文に切り替えます。組織のネットワークから
diagrams.net に届かないとき、白いままでは理由が分からないためです。

配色は `dark=0/1` として URL に載せるしかないので、テーマを切り替えたときは
iframe を読み込み直します（`Drawio.reload`）。プレビュータブを閉じるときは
`about:blank` へ飛ばして diagrams.net のページを止めます。図のタブを 2 枚開けば
iframe も 2 つになるので、どちらから来たメッセージかは `contentWindow` で見分けます。
**「読み込んだか」は `tab.pv.drawio.loaded` で持っています**。`iframe.src` は URL を
反映する属性で、`''` を代入しても getter は（空文字列をこのページの URL として
解決した結果）このページの URL を返すため、src では判定できません。

#### 表（CSV / TSV）

`.csv` と `.tsv` は表で見られます（`client/app/215-csv-grid.js`・`216-csv-grid-edit.js`）。
解析と、表の操作を本文の変更に直す部分は `client/lib/csv.js` にあり、単体テストがあります。

- **読み方**：引用符で囲んだ値の中のカンマ・改行・`""` を扱います。区切りは `.tsv` ならタブ、
  `.csv` ならカンマで、カンマが 1 つも無くセミコロンかタブがそろって出るときだけそちらにします
  （欧州の Excel の CSV）。区切りは最初に開いたときに決め、編集の途中では決め直しません。
  Shift_JIS の CSV も、エディタで開いた時点で文字に直っているのでそのまま表になります
- **表示**：1 行目を見出しにして上端に固定します（バーで切り替え可。切ると A, B, C…）。
  行番号は左端に固定し、押すとエディタのその行へ移ります。8 割以上が数値の列は右寄せです。
  セル内の改行は `↵` で 1 行に畳み、全文はツールチップで出します
- **速さ**：行の高さを 26px に固定し、見えている行と前後 12 行だけを DOM にします
  （2 万行で描き始めまで 26ms、DOM の行は 40 行弱）。列の幅は先頭 400 行から見積もって固定します。
  本文が同じ（CodeMirror の `Text` が同じもの）なら解析し直しません
- **並べ替え**：見出しを押すたびに 昇順 → 降順 → 元の順。両方が数値として読めれば数値で
  （`1,200`・`¥5,000`・`12%` も数値）、それ以外は日本語の自然順で比べます。空のセルは向きに
  かかわらず最後です。見出しの右クリックからも選べます
- **絞り込み**：バーの入力欄で、すべての列か選んだ列の部分一致（大文字小文字を区別しない）
- 並べ替えと絞り込みは**表示の上だけ**の操作で、本文の行の順は変えません
- **安全**：セルは `textContent` で入れるだけなので、共有された CSV に何が書かれていても
  HTML やスクリプトとしては動きません。`=` で始まる値も数式としては扱いません

##### 表の上での編集

| 操作 | キー・マウス |
|---|---|
| セルを選ぶ | クリック / 矢印キー / `Tab`・`Shift+Tab` |
| 編集を始める | ダブルクリック / `Enter` / `F2`（文字を打つと、そのセルを置き換えて始まる） |
| 確定して動く | `Enter`（下）/ `Shift+Enter`（上）/ `Tab`（右）/ 別の所を押す |
| セル内の改行 | `Alt+Enter`（Excel と同じ） |
| やめる | `Esc` |
| 空にする | `Delete` / `Backspace` |
| コピー・切り取り・貼り付け | `Mod+C` / `Mod+X` / `Mod+V` |
| 元に戻す・やり直し | `Mod+Z` / `Mod+Shift+Z`（`Mod+Y`） |
| 行・列の追加と削除、列名の変更 | 右クリック（行の追加はバーの「行を追加」からも） |

- **表の上の変更は、元のタブの CodeMirror にトランザクションとして流します。**
  本文をまるごと組み立て直すのではなく、変えたセルの範囲だけを書き換えるので、触っていない
  セルの書き方（引用符の有無・空白）はそのまま残ります。そのため、未保存の印・自動保存・下書き・
  保存時の文字コード（Shift_JIS のまま）と改行コード（CRLF のまま）は、エディタで打ったときと
  同じ経路で効きます。元のタブがどのペインにも出ていなくても書き換えられます
- 値にカンマ・引用符・改行が入ると、そのセルだけ `"…"` で囲みます。元が引用符付きのセルは
  囲んだままにします
- **Undo は元のエディタの履歴**です。表の上の `Mod+Z` は、同じキー操作を元のエディタに渡して
  処理させます（読み込んでいるバンドルが undo コマンドを外に出していないため）。そのため、
  元のファイルがどこかのペインに出ているときだけ効きます。出ていないときは知らせます
- 並べ替え・絞り込み中にセルを書き換えても、**並びはそのまま**にします（書き換えた行が
  目の前から飛んでいかないように）。並べ直すには見出しを押し直します
- 行を足すときは、並べ替えと絞り込みを解除します（足した空の行が見えない所へ行かないように）
- 行の削除と列の削除は確認しません。`Mod+Z` で戻せます
- 貼り付けは、1 つの値なら選んでいるセルへ、タブと改行で区切られた塊（Excel やスプレッドシートの
  範囲をコピーしたもの）なら選んでいるセルを左上にして表示の順に書きます。**行が足りない所・
  その行に列が無い所には書きません**（表示の順が本文と違うと、足す位置が決められないため）。
  書かなかった数は知らせます
- 列を足すと、その位置より列の少ない短い行は触りません（ずれを広げないため）
- エディタで打っている途中（表の描き直しを待っている間）に表を操作しても、表を解析し直してから
  書き換えるので、古い位置を書き換えることはありません
- **キーを受けるのは、選んでいるセルの上に透明にして重ねた 1 枚の入力欄です**（Google スプレッドシートと
  同じ作り）。セルを選んでいる間はずっとここにフォーカスがあるので、表の上でいきなり日本語を
  打っても変換はこの欄の中で始まり、始まった時点でこの欄をそのまま編集欄として見せます。
  中身は選んでいるセルの値を全選択にしてあるので、打った文字・変換がそのまま置き換えになります。
  コピーと切り取り・貼り付けも、編集できる要素の上で起きるので、どのブラウザでも届きます
- **IME の変換の確定の `Enter` では決定しません**
- セルを選ぶのは `mousedown` です。`click` まで待つと、編集中だった欄の確定で表が描き直され、
  押したセルの要素が入れ替わって `click` が届かないことがあるためです
- **閉じていない引用符（`"`）があると、表からは編集できません。** そのセルは文末までの範囲を持つので、
  書き換えると後ろが全部消えてしまうためです。バーに何行目かを出すので、エディタで直してください
- 編集している間に本文が変わったとき（裏での再読み込み・変更ログでの差し替え・別のペインでの入力）は、
  同じセルがまだ同じ値のときだけ書きます。そうでなければ別の行に書いてしまうおそれがあるので書かず、
  入力した値はクリップボードに入れて知らせます
- 見出しにした・絞り込んだなどで見えなくなった行のセルは、選択を外します（見えないセルを
  `Delete` で消したり貼り付けたりしないように）
- 空のファイルで「行を追加」を押すと、見出しの行（列名）から書き始めます

### Markdown の入力バー

`.md` のタブを開いているときだけ、エディタの上にボタンを並べます（設定で消せます）。
見出し・太字・斜体・打ち消し・コード・引用・箇条書き・番号・チェックリスト・
リンク・表・コードブロック・Mermaid・区切り線。

いずれも選択範囲に対するトグルで、押し直すと元に戻ります。ボタンの `mousedown` を
止めているのは、押した瞬間にエディタの選択が外れるのを防ぐためです。

キーバインドは足していません。`Mod+B` はサイドバー、`Mod+I` にもブラウザ既定の
動作があり、**Markdown のタブでだけ意味が変わる**のは事故のもとだからです。

### スマホ表示

幅 768px 以下（と、高さ 520px 以下の指で操作する端末＝横向きのスマホ）では、
`client/app/245-mobile.js` の `Mobile` が `.app--mobile` を付けて振る舞いを変えます。
見た目はほぼ CSS（`src/css.html` の「スマホ」の節）で、JS で変えているのは次だけです。

| 何を | どう変えるか |
|---|---|
| サイドバー | アクティビティバーごとドロワーにする。ヘッダーの ☰ で開閉し、ドロワーから開いたファイルが表示されたら閉じる（`Mobile.onTabShown`）。開閉は `Layout.sidebarHidden` とは別に持ち、セッションには書かない |
| サイドバーの幅 | `Layout.clamp` が丸めない。スマホの画面幅で丸めた値を、PC と共有しているセッションへ持ち帰らないため |
| ペイン | `Panes.split` / `splitRoot` が null を返す（分割しない）。セッションに分割の記録があっても木は崩さず、CSS で操作対象の 1 枚だけを出す。タブバーの先頭に「1/2」のようなボタンを出し、押すと次のペインへ移る |
| プレビュー・ターミナル・横に開く | 隣のペインではなく、同じペインのタブとして開く |
| キーボードの代わり | ヘッダーに 元に戻す・やり直し・保存（一時メモなら保存先を決める）・新しい一時メモ を出す。押してもエディタのフォーカスを奪わない（ソフトキーボードが閉じないように） |
| 右クリック | Android の Chrome は長押しで contextmenu を出すのでそのまま。iOS は出さないので、行・タブ・表のセルに限って 500ms の長押しを contextmenu として配る。メニューは画面の下から出す |
| ドラッグ＆ドロップ | タッチでは使えないので、ファイル・フォルダのメニューに「移動…」を足した（フォルダ選択画面で行き先を選ぶ。PC でも使える） |
| コマンドパレット | コマンド一覧を開いても入力欄にフォーカスしない（ソフトキーボードで一覧が隠れるため） |

ソフトキーボードの扱い:

- Android の Chrome は、viewport に `interactive-widget=resizes-content` を入れて画面の高さを縮めさせる
  （`src/Code.gs` の `META_TAGS`。既定では縮まず、下の行がキーボードに隠れる）
- iOS は画面が縮まないので、エディタにフォーカスがある間はカーソルを追う送りの下側に画面の 45% の余白を取り
  （`EditorView.scrollMargins`）、本文の末尾にも同じだけ余白を足す。カーソルが常に上半分にあるので、キーボードに隠れない
- viewport の `maximum-scale=1` は、iOS が 16px 未満の入力欄にフォーカスしたとき画面を拡大するのを止めるため。
  あわせてスマホでは入力欄を 16px、エディタの文字を 15px 以上にしている（設定の文字サイズが大きければそちらに従う）

### サイドバーの幅と表示状態

仕切りをドラッグで幅変更、ダブルクリックで既定（268px）に戻します。
`Mod+B` かヘッダーの ☰ で表示を切り替えます。

幅は画面幅の 60%、最小 160px に丸めます。ウィンドウを狭めたときも
丸め直すので、サイドバーだけが画面を占領する状態になりません。

状態はセッション（`UserProperties`）に保存します。`localStorage` を使わないのは
サンドボックス iframe だとリロードをまたいで残らないためです（後述の
「既知の制限」を参照）。保存が無い初回は CSS の既定値を実測して初期値にします
（`--sidebar-w` は画面幅によって変わるため、実測しないと最初のドラッグで幅が飛びます）。

幅を変えても `window` の `resize` は起きないので、CodeMirror には
`requestMeasure()` で測り直しを促しています。

### セッション復元

開いているタブとサイドバーの表示位置を `UserProperties` に記録し、リロード後に復元します。
記録するのは**ファイル ID・表示名・種別、展開中フォルダの ID、サイドバーの幅と
表示状態だけ**です（ルートフォルダ自体の開閉状態も展開中フォルダに含まれます）
（本文は持たせません。9KB 制限に収まらないうえ、真実の保存先は常に Drive のため）。
最大 20 タブ・40 フォルダで、超える場合は展開状態から先に落とします。

プレビュータブも復元します。記録するのは元のファイル ID と `kind: 'preview'` だけで、
復元時に `preview:<ファイル ID>` として組み立て直します（元のファイルのタブが
戻せなかった場合は、映すものが無いので作りません）。

ペインの分割も同じセッションに入れます（木の形・各ペインのタブ ID・表示中のタブ・取り分）。
9KB に収まらないとき（UTF-8 のバイト数で 8,000 を超えたとき。日本語の名前は 1 文字 3 バイトなので文字数では測れません）は **展開中フォルダ → 分割 → タブ** の順に落とします。分割が消えても
タブは 1 枚のペインに残るので、失うものが少ない順にしてあります。サーバー側は
枚数（6）と木の深さ（8）で蓋をしてから保存します。

展開されていたフォルダは `listEntriesMulti` で **1 往復にまとめて**取得します。
フォルダごとに `listEntries` を呼ぶと、展開数ぶんの往復が起動時に発生してしまうためです。

正はサーバー側（`UserProperties`）です。HtmlService のサンドボックス iframe は
リロードのたびに異なるオリジンになりうるためです（後述の「既知の制限」を参照）。

ただしサーバーへの送信は 1.5 秒のデバウンス付きの `google.script.run` なので、操作の直後に
リロードすると送信が間に合わず、最後の 1 操作が抜けていました。そこで**同じ内容を
`localStorage`（`gdte:session:<メールアドレス>`）にも即座に書きます**（同期書き込みなので
離脱に負けません）。どちらの記録にも `savedAt`（送った時刻）を付けておき、起動時の
スナップショットと `getBootstrap` の応答のそれぞれで、このブラウザの記録のほうが新しければ
そちらを使います。オリジンが変わって `localStorage` が空なら、従来どおりサーバーの記録で復元します。
キーにメールアドレスを入れているので、同じブラウザで別のアカウントに切り替えても混ざりません。

ピン留めはセッションとは別の値（`pins`）です。セッションは「前回の画面」で、
ピン留めは「よく使うファイル」なので寿命が違います。

**起動時に全タブの本文は読みません。** タブ数ぶん `readFile` が往復すると
コールドスタート時に数十秒かかるため、復元直後はタブの枠だけを並べ、
本文はアクティブなタブ 1 枚だけ読みます。残りは切り替えられた瞬間に読み込まれます
（未読み込みのタブはタブ名が斜体のグレーで表示されます）。分割していた場合、
アクティブでないペインの中身は最初の描画が終わってから順に読み込みます。

復元しようとしたファイルが削除済み・権限が外れていた場合は、そのタブを閉じて
次のタブを試します。

### 未保存内容の保険

編集中の内容は 500ms スロットルで `localStorage` に下書きとして書き込み、
保存成功時に消します。保存に失敗した状態でファイルを開き直すと復元を提案します。

- 開いていないファイルの下書きは、**30 日たつと起動時に消します**（`Draft.MAX_AGE_MS`）。
  共用 PC に平文のまま残り続けないように、また容量を食い潰さないようにするためです
- 容量不足で書けなかったときは、表示用の控え（`LocalSnap`）→ 開いていないファイルの下書きの
  古い順、に 1 件ずつ空けて書き直します。それでも書けなければ**一度だけトーストで知らせます**
  （下書きで守られているつもりのまま編集を続けないように）

#### 保存に失敗したら Drive にも退避する（`DraftStash`）

`localStorage` は再読み込みでオリジンが変わると読めなくなることがあるので、
**保存に失敗したときだけ**、同じ内容をマイドライブの
「`Googleドライブテキストエディタ / drafts`」にプレーンテキストとして書きます
（`<元のファイル名>.下書き.txt`。Drive で直接開いても読めます）。

- 退避ファイルには `appProperties`（`gdteDraft=1`・`gdteDraftFor=<元のファイル ID>`・
  退避した時刻・開いたときの更新日時）を付けます。起動後に 1 本の `files.list` で一覧を取り、
  そのファイルを開いたときに、`localStorage` に下書きが無ければ退避分で復元を提案します
- 開いていないファイルの退避分があれば起動時にトーストで知らせ、コマンドパレットの
  「退避した下書きを確認する」から元のファイルを開けます
- 自動保存の失敗が続いても、同じファイルへの書き込みは 15 秒に 1 回までです（最後の内容を書きます）
- 下書きが要らなくなったとき（保存できた・破棄を選んだ・元のファイルをゴミ箱へ移した）は
  `Draft.clear` から退避ファイルも消します。**消すのはこの仕組みが作った退避ファイルだけで、
  ゴミ箱を経由せず削除します**（残すと Drive のゴミ箱が退避ファイルで埋まるため）
- 直接 Drive API が使えないとき（GAS 経由で動いているとき）は退避しません。
  ネットワークが切れていて保存できない場合は退避もできないので、`localStorage` の下書きだけが頼りです

### コマンドパレットとクイックオープン

`Mod+P` でファイルのあいまい検索、`Mod+Shift+P` でコマンドの検索です。
あいまい検索は `fuzzysort` を初回に遅延読み込みし、**読み込めなければ部分一致に
フォールバック**します（CDN 到達性で起動時の機能を止めないため）。

コマンドは `commandRegistry()` に集約しています。`when` で実行可能条件を書けるので、
状況に合わないものは一覧に出ません。**機能を増やしたときに UI 上の置き場所を
探さなくて済む**のがこの仕組みの利点です。

#### クイックオープンはサブフォルダの中も探す（ファイル名の索引）

ツリーは開いたフォルダの中身しか持たないので、そのままでは `Mod+P` に出せるのも
展開した階層のファイルだけです。そこで **ルート配下のファイル名だけを集めた索引**
（`FileIndex`）を裏で作り、ツリーに無いものを候補に足しています。

- 作り方は全体検索のフォルダ列挙と同じく 1 段ずつ広げる方式で、`listEntriesMulti`
  （30 フォルダずつ・同時 4 本）を使います。往復はフォルダ数ではなく深さでほぼ決まります
- 起動が落ち着いた 4 秒後の空き時間に、索引が無いか 10 分より古ければ作ります
  （省データ設定・2G 判定では作らず、`Mod+P` を押したときに作ります）。`Mod+P` を
  開いたときに古ければその場でも作り直し、できた時点で候補を差し替えます
- 結果は `localStorage`（`gdte:fileindex`）に詰めた形で残し、次の起動では Drive を
  待たずに使います。ルートの組み合わせが変わると使いません
- ツリーに載っているファイルはツリーの情報を優先します（改名・移動が即座に反映されるため）。
  ツリーから消えたファイルは索引からも落とします。それ以外の食い違い（他の人が
  消した・動かしたなど）は、次の作り直しで直ります
- 上限は深さ 8 段・フォルダ 1,000 個・ファイル 10,000 件。打ち切ったときはパレットの
  下端に「範囲が広いため一部まで」と出ます
- 検索語が空のときは先頭 300 件だけを並べます（数千件を DOM にすると開くのが遅れるため）

中身で探すときは `Mod+Shift+F` の全体検索を使ってください。

`Mod+P` はブラウザの印刷ダイアログを奪うので、capture フェーズで止めています。

### アイコン

`src/icons.html` に **SVG スプライトを同梱**しています（Lucide v1.43.0、ISC）。
`<symbol id="i-xxx">` を並べた非表示の `<svg>` で、JS 側は `icon('name')` ヘルパ、
HTML 側は `<svg class="icon"><use href="#i-name"/></svg>` で参照します。

**ウェブフォント（Codicons 等）や CDN から読まずに同梱しているのは:**

- エディタ本体（vendor バンドル）以外に実行時の外部依存を増やしたくない
- フォント読み込みに失敗したときに豆腐や空白が出るのを避けたい

stroke ベースなので `currentColor` で親の文字色に追従します。大きさは `1em` 基準で、
`.icon--sm` / `.icon--lg` で上書きします。種別の色分け（フォルダは黄土色など）は
`.icon--folder` / `.icon--file` / `.icon--pdf` / `.icon--warn` / `.icon--muted` です。

**アイコンを追加・差し替えるとき**は、Lucide から SVG を取り、外側の `<svg>` 属性を落とした中身だけを `<symbol>` に入れます。

```
curl -s https://cdn.jsdelivr.net/npm/lucide-static@1.43.0/icons/<name>.svg
```

`fill` / `stroke` / `stroke-width` は `.icon` の CSS 側が持つので、`<symbol>` には入れません。

### 配色

VS Code の Dark Modern / Light Modern（現行の既定テーマ）に合わせています。
アプリ側の CSS 変数と、CodeMirror のテーマ／トークン色の両方です。

**切り替えは 3 択**（設定 `themeMode`）で、既定は `system` です。

| 値 | 意味 |
|---|---|
| `system` | OS の設定（`prefers-color-scheme`）に従う。OS 側を変えたその場で追従する |
| `light` | 常にライト |
| `dark` | 常にダーク |

入口は 3 つあり、どれも同じ設定を書き換えます。

- ヘッダー右のアイコン（いまの設定に応じて ☀ / ☾ / 🖥 に変わる）
- サイドバーの設定の「外観」
- コマンドパレットの「外観を変更（ライト / ダーク / システム）」

#### 仕組み

CSS は**ダークを既定**にし、`:root[data-theme="light"]` で色トークンだけを
差し替えます（`src/css.html`）。`data-theme` は次の順で決まります。

1. `doGet` が `UserProperties` の `settings.themeMode` を読み、
   テンプレート変数 `themeMode` として `<head>` に渡す（`themeModeFor_`）
2. `<head>` のインラインスクリプトが、それと `matchMedia` から
   `light` / `dark` に解決して `<html data-theme>` を付ける
3. 以降は `client/app/180-theme.js` の `Theme` が付け替える（設定変更・OS の変更）

**1 と 2 を `<head>` でやっているのが要点**です。前回の状態を埋めた
`window.__BOOT` は `<body>` の末尾にあり、そこまで待つとライト設定の人に
一瞬ダークが出ます。配色だけは別の経路で先に渡しています。

`matchMedia` が使えない環境ではダークになります（従来と同じ）。

#### CSS 変数では届かない 3 か所

`Theme.apply()` が、トークンの差し替えと合わせて次も切り替えます。

| | やっていること |
|---|---|
| CodeMirror | `Editor.themeCompartment` を差し替える（`Editor.setTheme`）。テーマの `dark` フラグが変わると CM6 が `&light` / `&dark` の解決に使うクラスも変わるので、インデントガイドの色も一緒に切り替わる |
| Mermaid | SVG に色を焼き込んで描くため、`initialize` をやり直して図のキャッシュを捨て、開いているプレビューを組み直す（`Preview.onThemeChange`） |
| drawio | 配色を URL（`dark=0/1`）で渡しているので iframe を読み込み直す（`Drawio.reload`） |

HTML プレビューは**追従させません**。中身はユーザーが書いた 1 ファイル完結の
HTML で、その中の色指定は白地を前提にしていることが多いためです。

#### 色を足すとき

個別の色を CSS に直書きしないこと。片方のテーマでだけ読めない色ができます。
`:root` にトークンを足し、`:root[data-theme="light"]` にも値を書きます
（`src/css.html` の先頭にも同じ注意を書いてあります）。

なお警告（`--warn`）とエラー（`--error`）のライト側は、VS Code の値
（`#bf8803` / `#e51400`）そのままだと白地で薄く読みにくいため、
読める濃さまで落とした値にしています。

#### CM6 のテーマを自作している理由

CM6 のテーマは**既製パッケージを使わず自作**しています
（`client/app/190-codemirror.js` の `cmTheme` / `cmHighlightStyle`、色は `CM_UI` / `CM_TOKENS`）。
既製のテーマパッケージは `@codemirror/view` や `@lezer/highlight` を
取り込むため、import map での外部化を 1 つ間違えるとコアが二重になって
`Unrecognized extension value` で壊れます。そのリスクを増やさないためです。
色の値は VS Code のテーマ定義から取っています。

インデントガイドは `@replit/codemirror-indentation-markers` です。

### 検索置換パネルの日本語化

`EditorState.phrases` に日本語を流し込んでいます（`client/app/190-codemirror.js` の `PHRASES`）。
キーは各パッケージが `state.phrase(...)` に渡す英語リテラルそのもので、
**キーが 1 文字違うと翻訳が当たりません**。CM6 を更新して未翻訳の文字列が出た場合は、
該当パッケージのソースを `grep 'phrase('` して実際のキーを確認してください。

なお CM6 の検索パネルは 1 つで検索と置換の両方を兼ねます（VS Code の
`Cmd+Shift+F` に相当する別パネルはありません）。
